# `tools/probes/` —— 入库的可复现探针

> 本目录放**离线、免网络、免模型、确定性**的探针：它们回答具体问题并**打印数字**，
> 与被门禁调用的单测互补（单测判"是否退化"，探针报"现在是多少"）。
>
> 来由（G21，2026-10-03）：本仓此前的行为判据有 26 个 `.mjs` 探针躺在 **gitignored 的 `.omniharness/`**
> 里——GitHub 上不存在、CI 不跑、别人复现不了。"**能被他人复现**"是判据可信的前提，故把其中最有价值的搬进仓库。

## 复现配方（干净克隆）

```bash
git clone <repo> && cd <repo>
npm ci
npm run build          # 探针 import dist/**（与单测同一份编译产物）
node tools/probes/recallHitrate.mjs
node tools/probes/toolExposureBudget.mjs
node tools/probes/rerankDiscriminatorAb.mjs 14
```

数字随语料变化而变化（`src/` 每加一个文件都会影响召回）⇒ **跨提交比较必须同语料**；
本节的"实测参考值"用于确认**数量级**一致（不是逐位相等）。

## 探针清单

### 1. `recallHitrate.mjs` —— 检索命中率（生产口径）

| 项                                                          | 内容                                                                                               |
| ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 回答什么                                                    | 生产口径（`fileK` ± 精排）下，冻结查询集的 hitRate@K 与 **配对 bootstrap 95% CI**                  |
| 语料 / 查询                                                 | 仓库 `src/`（`morph` 开、`light` 档）；`tests/fixtures/recallQueries.ts`（冻结 core + 扩样 ext）   |
| GT 口径                                                     | 文件正文含锚点字面量即真值（机械推出，**不依赖 BM25** ⇒ 无自证循环）                               |
| 用法                                                        | `node tools/probes/recallHitrate.mjs [--fileK=N] [--rerank] [--json=out.json]`                     |
| 实测参考值（2026-10-03，926 文件 / 10,599 符号 / 192 查询） | `fileK=20` 不精排：**all 40.6% [33.9, 47.4]**、**core 68.8% [53.1, 84.4]**、ext 35.0% [28.1, 42.5] |
| 诚实边界                                                    | 只测**文件级命中**，不测符号级精确率；`ext` 段可比性弱于冻结的 `core` 段                           |

### 2. `toolExposureBudget.mjs` —— 工具暴露规划（可见工具数 + 真实 schema token）

| 项                       | 内容                                                                                                                                                                                                                         |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 回答什么                 | `ToolExposurePlanner` 的 `off` / `plan` 两种模式下，**直载给模型的工具数**与**真实 schema 的估算 token 代价**（G21-b 已接真实 schema）                                                                                       |
| 输入                     | `src/ports/tool/toolNames.ts`（工具名单一来源，实测 **46** 项）+ 8 条代表性任务文本；schema 取自 `ConfigFactory.build({ workspaceRoot })`（**离线**生产装配入口，默认注册 **33** 个工具）                                    |
| 用法                     | `node tools/probes/toolExposureBudget.mjs [--task="…"] [--json=out.json]`                                                                                                                                                    |
| 实测参考值（2026-10-03） | 工具总数 **46**；`plan` 可见 **20–46**（均值 28.9），**2/8 条任务不命中类别 ⇒ fail-safe 全放行**；**schema token**：off 全下发 **5,250**，plan 命中时 **953–1,677**（省 **3,573–4,297** ⇒ **68.1%–81.8%**），未命中省 **0%** |
| 诚实边界                 | schema token 由 `TokenEstimator` **估算**（启发式，非真 tokenizer）；只含工具 schema（name/description/parameters），**不含工具结果**；**名字表(46) ⊃ 默认注册集(33)**（条件注册的 LSP/MCP/媒体等不出现）                    |

### 3. `rerankDiscriminatorAb.mjs` —— 精排判别器受控对照

| 项                                      | 内容                                                                                                                                                    |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 回答什么                                | 换精排**判别器**（同一候选池、同一公式骨架，只换一项）是否有增益；含**第二段净效果**                                                                    |
| 方法                                    | 成对 bootstrap 95% CI **+** repeated 2-fold 留出折（本仓「两关」纪律），判定函数内置                                                                    |
| 用法                                    | `node tools/probes/rerankDiscriminatorAb.mjs [K] [--pool N] [--only=V12,V13] [--json=out.json]`                                                         |
| 实测参考值（2026-10-03，K=14/192 查询） | 基线 V0 `hit@14 33.3% / recall 21.2% / MRR 0.130`；**全部变体结论均为「不成立」（CI 跨 0 或折负）**；第二段净效果 `MRR ΔCI [−2.28, 2.27]pp`、折负 20/40 |
| 诚实边界                                | 变体在**探针内**实现（不改生产代码）⇒ 衡量的是"若换会怎样"；只过一关（CI 或折）**不算**增益                                                             |

### 4. `memoryLiftProbe.mjs` —— 记忆 primer 的**机制级**判据

| 项                       | 内容                                                                                                                                                                                             |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 回答什么                 | primer 注入的**回灌内容**是否相关、覆盖率多少、代价多大，以及这套判据**有没有判死能力**                                                                                                          |
| 口径                     | **机制级**（注入覆盖率 / 相关性 hitRate@5 / 回灌 token）；**不是** LLM 任务增益——离线无 key 时做任务级 A/B 只会测到自己的脚本模型（假数字）                                                      |
| 方法                     | 自建夹具（8 条事实各带唯一锚点词 + 10 条查询）→ 三档对照（primer 关 / 开 / **随机注入**）+ 配对 bootstrap CI + repeated 2-fold 留出折                                                            |
| 用法                     | `node tools/probes/memoryLiftProbe.mjs [--k=5] [--json=out.json]`（退出码 **3** = 判死能力自证失败）                                                                                             |
| 实测参考值（2026-10-03） | primer 关：覆盖率 **0%** / 相关性 **0%**；primer 开：覆盖率 **80%** / 相关性 **100%**，ΔCI **[50,100]pp**、折负 **0/40**；**随机对照（覆盖率 100%）相关性 37.5%**（ΔCI [20,80]pp）⇒ **有区分力** |
| 诚实边界                 | 夹具不代表真实记忆库分布；相关性用"锚点命中"机械判定 ⇒ 测的是**检索机制**，不是"这条事实对不对"；primer 关时覆盖率为 0 是构造性的，不是"测出来的增益"                                            |

## 约定（新增探针必须满足）

1. **离线**：不起网络、不调模型、不读用户级配置；只依赖仓库文件 + `dist/**`。
2. **确定性**：随机过程一律固定种子（跨机同结果）；不写时间戳进判定量。
3. **可复现**：`node tools/probes/<name>.mjs` 直接可跑；缺编译产物时给出**可执行**的提示并非零退出。
4. **只报数、不判定**（除非判定本身就是口径，如两关统计）：结论写进文档，别把结论藏进退出码。
5. **`--json=` 输出**：机器可读，便于后续对照与自动化。
6. **`docs/` 口径**：探针文件头写明「回答什么 / 口径 / 前置 / 诚实边界」四段——本仓的"口径"事故大多源于缺这四段。
7. **登记**：新探针要加进本 README 的清单，并由 `tests/unit/probesInRepo.test.ts` 核对（漏登记即红）。
