# `tools/probes/` —— 入库的可复现探针

> 本目录放**离线、免网络、免模型、确定性**的探针：它们回答具体问题并**打印数字**，
> 与被门禁调用的单测互补（单测判"是否退化"，探针报"现在是多少"）。
>
> 来由（G21，2026-10-03）：本仓此前的行为判据有 26 个 `.mjs` 探针躺在 **gitignored 的 `.omniharness/`**
> 里——GitHub 上不存在、CI 不跑、别人复现不了。"**能被他人复现**"是判据可信的前提，故把其中最有价值的搬进仓库。

## 复现配方（干净克隆）

```bash
git clone <repo> && cd <repo>
npm ci
npm run build          # 探针 import dist/**（与单测同一份编译产物）
node tools/probes/recallHitrate.mjs
node tools/probes/toolExposureBudget.mjs
node tools/probes/rerankDiscriminatorAb.mjs 14
```

数字随语料变化而变化（`src/` 每加一个文件都会影响召回）⇒ **跨提交比较必须同语料**；
本节的"实测参考值"用于确认**数量级**一致（不是逐位相等）。

### 4. `memoryLiftProbe.mjs` —— 记忆 primer 的**机制级**判据

| 项                       | 内容                                                                                                                                                                                             |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 回答什么                 | primer 注入的**回灌内容**是否相关、覆盖率多少、代价多大，以及这套判据**有没有判死能力**                                                                                                          |
| 口径                     | **机制级**（注入覆盖率 / 相关性 hitRate@5 / 回灌 token）；**不是** LLM 任务增益——离线无 key 时做任务级 A/B 只会测到自己的脚本模型（假数字）                                                      |
| 方法                     | 自建夹具（8 条事实各带唯一锚点词 + 10 条查询）→ 三档对照（primer 关 / 开 / **随机注入**）+ 配对 bootstrap CI + repeated 2-fold 留出折                                                            |
| 用法                     | `node tools/probes/memoryLiftProbe.mjs [--k=5] [--json=out.json]`（退出码 **3** = 判死能力自证失败）                                                                                             |
| 实测参考值（2026-10-03） | primer 关：覆盖率 **0%** / 相关性 **0%**；primer 开：覆盖率 **80%** / 相关性 **100%**，ΔCI **[50,100]pp**、折负 **0/40**；**随机对照（覆盖率 100%）相关性 37.5%**（ΔCI [20,80]pp）⇒ **有区分力** |
| 诚实边界                 | 夹具不代表真实记忆库分布；相关性用"锚点命中"机械判定 ⇒ 测的是**检索机制**，不是"这条事实对不对"；primer 关时覆盖率为 0 是构造性的，不是"测出来的增益"                                            |

### 5. `evolutionLiftProbe.mjs` —— 进化闭环的**机制级**增益判据（E2+）

| 项                       | 内容                                                                                                                                                                                                                                                                                                                                 |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 回答什么                 | 「进化闭环（twist 重组 → 门禁 → 晋升）相对**固定技能集**，有没有任务级增益？」以及**瓶颈在搜索还是门禁**、判据**有没有判死能力**                                                                                                                                                                                                     |
| 口径                     | **机制级**：工况桶适配度（技能场与目标场的归一化相关）的**配对**开/关差值；**不是** LLM 任务成功率（离线无模型时那只会测到自己的脚本模型）                                                                                                                                                                                           |
| 方法                     | 自建夹具（48 工况桶 = 单片族 + **按算子同构造生成的拍频族**，16 种子技能，40 池技能）→ 三条臂（OFF / ON / **结构性零对照**）→ 两关统计（配对 bootstrap 95% CI 不跨 0 **且** repeated 2-fold 折负 0）+ **val/test 纪律闸** + 事后敏感性与选父宽度诊断                                                                                 |
| 用法                     | `node tools/probes/evolutionLiftProbe.mjs [--buckets=48] [--rounds=3] [--json=out.json]`（退出码 **2** 缺编译产物 / **3** 判据无区分力 / **4** 纪律违规）                                                                                                                                                                            |
| 实测参考值（2026-10-04） | 预注册配置（每桶取最优 2 个父）：评估 87 / **晋升 1**，配对均值 **+0.016**，CI95 **[0, 0.045]**，折 +11/−0 ⇒ **不显著**（下界触 0）⇒ 按 E2 纪律进化**保持默认关**；诊断（前 4 个技能两两组合）：评估 522 / 晋升 12，配对均值 **+0.157**，CI95 **[0.040, 0.321]**，折 +20/−0 ⇒ **过两关**。零对照（候选=父副本）恒为 0 ⇒ 判据有区分力 |
| 诚实边界                 | 夹具**对机制友好**（拍频目标按算子同构造生成）⇒ 报出的增益只说明「目标族与该算子匹配时机制有效」，**不能**外推为生产增益；适配度是"场相关"这种机械量，不是语义相关；未测真实模型任务成功率与真实遥测驱动的候选分布                                                                                                                   |

> **本探针的因果结论（比增益数字更重要）**：同一算子 + 同一门禁下，
> **选父搜索宽度**从「每桶最优 2 个父」放宽到「前 4 个技能两两组合」即可从"不显著"变为"两关显著"。
> ⇒ 进化环的瓶颈在**候选搜索宽度**，不在门禁严格度（敏感性分析显示阈值放宽到 0 也只从 0 晋升变 1 晋升）。
> 纪律：诊断行**不得**用来挑参数上报（挑参数＝测试集参与选型）；主判定永远取预注册配置。

## 约定（新增探针必须满足）

1. **离线**：不起网络、不调模型、不读用户级配置；只依赖仓库文件 + `dist/**`。
2. **确定性**：随机过程一律固定种子（跨机同结果）；不写时间戳进判定量。
3. **可复现**：`node tools/probes/<name>.mjs` 直接可跑；缺编译产物时给出**可执行**的提示并非零退出。
4. **只报数、不判定**（除非判定本身就是口径，如两关统计）：结论写进文档，别把结论藏进退出码。
5. **`--json=` 输出**：机器可读，便于后续对照与自动化。
6. **`docs/` 口径**：探针文件头写明「回答什么 / 口径 / 前置 / 诚实边界」四段——本仓的"口径"事故大多源于缺这四段。
7. **登记**：新探针要加进本 README 的清单，并由 `tests/unit/probesInRepo.test.ts` 核对（漏登记即红）。

## 为什么另外两类（前缀 / 工具暴露）此前"没有探针"

报告 G21 点名"检索 / 前缀 / 工具暴露"三类。复核结果：

- **检索**：有独立探针（见上 1、3），已提升；
- **前缀复用**：判据已在仓库内——`tests/unit/prefixReuseGuard.test.ts`（同 `--test` 输出里带数字）；
- **工具暴露**：判据已在仓库内——`tests/unit/toolExposurePlanner.test.ts`；其"数字形态"由上面第 2 号探针补齐。

即："或并入 G1"这一分支对这些类别成立：它们**本就在仓库里**，缺的是"报数字"的形态，故只补了第 2 号探针。
