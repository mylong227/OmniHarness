# OmniHarness 全面升级总看板（2026-09-12 · v2 整合版）

> **本看板是唯一执行口径**：工程债（P0–P8）与技术升级（T0–T6）**共用同一套标准**——
> 同一张任务卡格式（现状证据 / 动作 / 可证伪验收 / 状态）、同一套门禁、同一条提交纪律。
> 目标：把「零依赖 + 六边形 + 强类型」的架构承诺，从**文档与宣称**落到**可机械校验的门禁与实测数字**上；
> 同时把最新的技术升级（成熟度治理 / 度量升级 / 记忆 / 验证闭环 / 训练信号 / 栈升级）纳入同一约束。
>
> 口径：所有「现状」均来自实测（`scripts/auditStandards.mjs` AST 全量扫描 + `scripts/check.mjs --strict` + 子代理代码审计 + 同 corpus AB 评测），**不采信任何自我宣称**。
> 纪律：每个任务独立提交，完成即跑四闸门（typecheck / build+test / lint / check），全绿才勾选。
> 状态图例：⬜ 待办 · 🟡 进行中 · ✅ 已完成（含 commit 短哈希） · ❌ 实测判负（保留结论） · ⏸️ 暂缓（有明确理由）

## 2. 目标架构与升级硬规则

### 2.1 依赖方向（唯一铁律，将被门禁强制）

```
        ┌──────────────── 组合根（唯一 new 具体实现的地方）────────────────┐
        │  config/ConfigFactory + core/Container + ServiceKeys            │
        └───────────────┬──────────────────────────────┬─────────────────┘
                        │ 装配注入                      │ 装配注入
                        ▼                              ▼
   src/ports/**  ◄── 依赖 ──  src/core/**        src/adapters/**  ──► 实现 ports
   （纯接口 + 纯类型）        （只依赖端口）         （唯一允许 IO / 第三方）
        ▲                                              │
        └──────────────── 禁止 core → adapters 直连 ────┘
```

1. `src/ports/**` 只含接口与纯类型（`ports/model.ts` 的两个 Error 类须迁出）。
2. `src/core/**` 禁止 import `adapters/**`（现状 8 处违规）。
3. `src/adapters/**` 禁止 import `core/**` 具体实现/单例（现状 9 处违规）。
4. 具体实现的 `new` 只允许出现在组合根与测试。
5. 模块级 `export const x = new Y()` 仅允许无状态/纯常量用途。

### 2.2 目录与归属规范

- **一域一目录族**：`ports/<域>.ts` + `adapters/<域>/**` + 域工具，禁止同名域散落 3 个以上顶层目录。
- **目录规模上限**：单目录文件数 ≤30（`adapters/tool` 38 待拆）。
- **一文件一类**：文件名 camelCase = 主类名 PascalCase（`ports/**` 接口文件豁免）。
- 新增目录须在 `docs/ARCHITECTURE_SPEC.md` 归属表登记。

### 2.3 写法规范

| 项           | 要求                                                                          | 门禁化                    |
| ------------ | ----------------------------------------------------------------------------- | ------------------------- |
| 语言         | TS + ESM + strict；禁 `var`/`any`/`@ts-ignore`                                | ✅ ESLint                 |
| 访问权限     | 每成员显式 `public`/`private`/`protected`                                     | ✅ ESLint（热区豁免待撤） |
| 面向对象     | 有状态/内聚操作收敛为类；**纯函数不得为 OO 而 OO**                            | 人工评审                  |
| 注释         | 类（作用）/ 字段 / 方法（职责）/ `@param` / `@returns` 必须有 JSDoc           | ⬜ 待建（P4.4）           |
| 单例         | 慎用；有状态者从组合根注入                                                    | ⬜ 待建                   |
| 大函数       | 函数体 ≤80 行（启发式大括号匹配）                                             | ✅ `check.mjs`            |
| 大文件       | ≤800 行                                                                       | ✅ `check.mjs`            |
| 无硬编码路径 | 一律 `CONFIG` + 环境变量派生                                                  | ✅                        |
| 前端         | 组件一律 class；render 内禁内联匿名函数；生命周期对齐；`this.state` 替代 hook | ⬜ 待建                   |

### 2.4 技术升级纳入同一标准的三条硬规则（**D5 的可执行化**）

1. **新技术代码零新增违规**：引入新模块前先跑 `npm run check -- --strict` 与 `auditStandards`；出现新违规**当场清零**，不得挂账。
2. **新机制必须声明成熟度 + 证据**：落入 `src/**` 的隐喻/机制引擎必须有 `@maturity Lx — 判据` 与 `@maturityEvidence <测试>`，L2/L3 无证据即门禁红（T0 门禁，已生效）。
3. **新排序/检索路必须过两关**：否决器（第 1 关）+ 同 corpus AB（第 2 关，bootstrap 95% CI）。**只过第 1 关不得声称有效**（D6）。

## 5. 进度跟踪机制

1. **每任务独立提交**，提交信息带任务 ID（如 `refactor(t2.5): 新技术代码合规收口`）；本看板勾选并填 commit 短哈希。
2. **每阶段收口**跑全门禁：`npm run check -- --strict` + `npm run typecheck` + `npm test` + `npm run test:integration` + `npm run lint` + `npm run audit:maturity` + `npm run eval:veto` + `npm run eval:ci`；全绿才推进下一阶段。
3. **度量口径唯一来源**：`node scripts/auditStandards.mjs`（扩展后含 P0.2 四类新度量），数字进 §4。
4. **架构约束机械可证**：P0.4 上线后，core→adapters / ports 纯度 / 目录规模由脚本判定，不靠人工评审。
5. **技术升级必须过两关**（D6）：否决器 + 同 corpus AB（bootstrap 95% CI），CI 跨 0 即判噪声，**不得声称有效**。
6. **允许白名单递减**：先冻结现状、新增即红、存量按批清偿。
