## 0. TL;DR：本质飞跃是什么

**今天**：harness 把"能力"当**配置**——工具启动时注册、技能是出厂 JSON、进化是主循环旁的可选支路。
**目标态（Evolvix-Ω）**：harness 把"能力"当**受治理的状态**——一切能力（技能/工作流/工具封装/
评估器/**进化算子本身**）成为统一资产：可注册、可进化、可审计、可回滚、可分发。
系统的定义成为它自己搜索空间的一部分——**这是"进化上限不受限制"的架构学含义**。

三个杠杆，缺一不可：

1. **治理原语统一为资产操作系统**（五层架构，§3；UCE 四公理映射，§2）；
2. **D10 择优准入**：能买的不自建，省下的维护成本全部投进治理与进化层——
   稳定性由端口隔离保证（依赖可换、架构不塌），不是靠"什么都自己写"；
3. **开放上限三层**（资产类型开放 / 元进化 / 任务共进化，§6），治理加倍不放野。

## 2. 设计公理（自研宣言 → 治理宣言；映射本仓 UCE 四公理）

| UCE 公理 | Evolvix-Ω 落点         | 一句话                                                                                                             |
| -------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Ⅰ 归一   | **Ω-1 统一资产协议**   | 一切可进化对象实现同一 `CapabilitySchema`（类型自描述：schema + 评估契约 + 信任档 + 隔离档）；`Skill` 是第一个实例 |
| Ⅱ 守恒   | **Ω-2 状态变化全台账** | 任何资产变更 = 哈希链上一个条目；"系统变成了什么样"与"账上记了什么"恒等                                            |
| Ⅲ 演变   | **Ω-3 算子皆资产**     | 发现/变异/组合/课程算子、评估器、晋升策略都注册为资产——可被进化（元进化），治理加倍                                |
| Ⅳ 度量   | **Ω-4 度量是一等公民** | 每个资产类型自带评估契约；按工况分桶是基座机制；"在正确空间比较"由类型作者声明、门禁强制                           |

**底线公理（Ω-0 · 端口换自由，D10 固化）**：第三方依赖只能落在适配层（`adapters/tools/cli/util/
search/context` 等），`ports/**`、`core/**` 恒第三方-free；每个依赖必须通过"**明天停更，换掉它改几个
文件？答案是 1 个适配器文件**"的退出测试。自研实现同题检验：**维护它每年花的人日，就是它的价格**——
价格高于成熟第三方且能力无差，按 D10 切换生产路径。

## 3. 五层目标架构

```
L4 分发层（生态）    签名资产包(.ohb+Ed25519) → 私有源 → 注册表元数据(MCP Registry 风格) → 市场
L3 治理层（策略）    晋升策略管线 + PromotionLedger + 回滚
                     信任-隔离阶梯: core(进程内) → signed(vm) → evolved(wasm: wasmtime 运行时) → OS 沙箱
L2 进化层（算子）    EvolutionKernel 七环编排 + OperatorPort / EvaluatorPort / ArchivePort 可插拔
L1 资产层（协议）    CapabilitySchema + CapabilityRegistry（SkillRegistry 绞杀者迁移，Skill=首个实例）
L0 执行底座（不变式）审批→沙箱→执行→记录 fail-closed 链 · 审计哈希链 · checkpoint/rewind · 事件流单源
```

- **L0（不变）**：六铁律、8 道门禁、事件流单源（ADR-0005）、审计哈希链（ADR-0004）。只使用，永不改语义。
- **L1（协议）**：`CapabilitySchema = { kind, version, validate(asset), evalContract, trustTier,
isolationLevel, ledgerSemantics }`。注册表协议是既有 `SkillPort` 的超集；**绞杀者迁移**：
  `SkillRegistry` 先实现新协议，既有注入路径（selectForPrompt→SkillSparsifier）逐位不变。
- **L2（算子）**：GEE Kernel v1 七环（Wave A）；算子/评估器以资产形式注册（L1），Kernel 按工况调度。
- **L3（治理）**：台账 + 回滚 + 信任-隔离阶梯。**v2 订正**：v1 把 omni-wasm 当 wasm 档"运行时"是
  错位——omni-wasm 是"把 omni-core 编译为 wasm"的**构建目标**，不是运行任意插件的运行时。
  v2 阶梯：`core`（内置，进程内）→ `signed`（VM 档：`node:vm` 现状，诚实标注 best-effort）→
  `evolved`（wasm 档：**wasmtime 运行时**（§5 A 级准入）+ omni-wasm 产出的 .wasm 技能模块）→
  OS 沙箱（policy/restricted 现状沿用）。每档对应 `trustTier`，`evolved` 强制台账。
- **L4（分发）**：签名资产包流水线 + 元数据导出（MCP Registry 字段风格），与 MCP 生态互描述不互依赖。

## 6. 上限设计：进化上限不受限制（v1 保留，原文有效）

1. **资产类型开放（轴 1）**：新 `CapabilitySchema` 运行时可注册（签名资产包）——每接入一种类型，
   进化搜索空间扩大一个维度，Kernel/治理层零改动。
2. **元进化（Ω-3）**：算子/评估器/策略本身是资产 ⇒ 可被进化；治理加倍（两层门禁 + 默认人工审批）。
3. **任务共进化（Wave E，POET/MCC 机理）**：任务集是资产、课程生成器是算子；红线：共进化产物
   仍过两关，无外部反馈的自我精炼循环永不启用。

诚实边界：模型权重与底层模型能力不在搜索空间内（GPU RL 不做）——"上限不受限制"指 harness 侧
可进化对象的空间在协议上无封顶，不是"无限智能"承诺。

| 跨资产类型全局事务（多资产原子晋升）           | 台账分链 + 补偿性回滚；复杂度不匹配单人维护                                                                 |
