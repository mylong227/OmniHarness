# OmniHarness 易用性 / 低学习成本 审计与优化（2026-10-09）

> **这份文档回答一个问题**：把 OmniHarness 交给一个**没见过它**的客户，他会在哪里卡住、卡住多久，
> 以及其中哪些是代码能解决的。
>
> 定位与前一轮的区别：本仓的既有投入几乎全在**工程严谨性**（fail-closed、判据、门禁、可复核数字）上，
> 这份审计看的是**产品可用性**轴——同一个能力，客户要花多少步、要懂多少内部术语才能用上。
>
> **记录纪律**（沿用看板口径）：每一条都附**本机可复核**的证据（命令 / 像素测量 / 截图路径），
> 并给出明确判定：**已修（带判据）** / **未修（写明原因与前置）**。禁止"以后再说"。

## 二、发现清单（按客户影响排序）

### F1. 悬停会话显示的是内部 ID，而标题被截断到约 14 字 —— **已修**

- **现象**：左栏默认「按项目分组」视图里一行只有截断标题；悬停给的是 `sess_muxrgioa_b`。
- **证据**（真机，工作区 15 条会话）：

  ```
  「在当前目录下先建...」「先读取工作区里的...」「先读取工作区里的...」  ← 两条完全同名
  title = sess_muxrgioa_b                                            ← 对客户零信息
  ```

- **影响**：左栏是**主要导航面**，"找到上次那条对话"在默认视图里做不到，只能逐条点进去试。
- **修复**：`web/src/ui/models/SessionRowMeta.ts`（新）——悬停给 **完整标题 + 最近活动 + 回合数 + id**，
  三个视图（按项目 / 按时间 / 卡片）共用。缺什么不编什么（`turns` 缺省时不写"0 回合"）。
- **判据**：`web/test/sessionRowMeta.test.mjs` ①②③（含"标题不得被截断"与"无时间不渲染"）。

### F2. 默认视图没有任何时间线索 —— **已修**

- **现象**：`N 回合 · X 分钟前` 只存在于**非默认**的卡片视图里，客户不会去发现。
- **修复**：两个分组视图的行内右侧加**紧凑**相对时间（`刚刚` / `3分` / `2小时` / `5天`）。
- **为什么是紧凑形**：这一格是从**标题宽度**里抠出来的。真机实测完整形（`3 分钟前`）会把标题
  从约 14 字压到约 6 字；紧凑形只占 18–35px。悬停文案里给的仍是完整形，信息一点没少。
- **判据**：`web/test/sessionRowMeta.test.mjs` ②（含"紧凑形必须真的更短"这条反向约束）。

### F3. 操作按钮以 `opacity:0` **常驻占位 86px** —— **已修**（本轮最大的宽度回收）

- **证据**（真机像素测量，248px 侧栏）：

  ```
  修前： label 73–91px（约 6 字）  time —      actions 86px（不可见却占位）
  修后： label 165–183px          time 18–35px  actions 96px（绝对定位，不参与布局）
  ```

  即：**标题宽度翻倍还多**，同时多出一个时间格。修前标题被"看不见的按钮"挤掉，而按钮只有悬停才需要。

- **修复**：`web/styles/polish.css` —— 操作按钮改为**绝对定位覆盖层**，左缘渐变过渡、右侧取行态底色。
- **代价与处置**：覆盖层会盖住标题尾巴，故必须自带不透明底（已在样式里显式还上，判据钉住）。
- **判据**：`web/test/sessionRowMeta.test.mjs` ④（`position:absolute` + 必须有 `background`）。

### F4. 中栏空态只说"会发生什么"，没说"我该输入什么" —— **已修**

- **现象（改动前的中栏全文）**：

  ```
  等待任务
  下达任务后，模型推理、工具调用与结果将在此实时呈现。
  ```

- **影响**：学习成本的最大来源不是功能复杂，而是**第一句话不知道怎么写**；第一次用的人最可能关掉页面。
- **修复**：`web/src/ui/models/StarterTasks.ts`（新）四条示例覆盖四条核心通路（读文件 / 跑命令 / 搜索 / 写代码），
  点一下**填进输入框**（`ComposerController.seedDraft`），可改后再发。
- **为什么是"填入"而不是"直接发送"**：示例是给人改的模板（文件名通常要换成自己的），
  且直接发送会**立刻消耗真实额度**——第一次点按钮就花钱，对客户是惊吓不是引导。判据把这条钉死。
- **判据**：`web/test/starterTasks.test.mjs` ①–⑤（含"不得直接 `onSend`"、"不得出现内部工具名
  `read_file`/`shell`"、"`seedDraft` 空文本 fail-closed + nonce 递增"）。
- **真机验收**：点第一个示例 ⇒ 输入框内容 =
  `读取工作区里的 README.md，用中文给我 5 行以内的摘要，并指出它最想解决的问题是什么。`，且已聚焦。

### F5. CLI 未知旗标只报"不认识"，不给"你是不是想用 X" —— **已修**

- **证据（改动前，实跑）**：

  ```bash
  node dist/src/cli/exec.js --modle foo
  # OmniHarness执行失败: 未知旗标 --modle（本 CLI 不认识它；用 --help 查看全部旗标。…）
  ```

  而 `--help` 是 **100+ 行**全量清单——真实使用里最高频的失败不是"用了不存在的功能"，
  而是**手滑打错一个字母**，此时客户要在几百行里找那个正确的名字。

- **修复**：`src/cli/flagSuggestion.ts`（新）。判据口径**宁缺勿滥**：
  只猜长旗标；归一化剥掉全部前导 `-`（`-model` ⇒ `--model`）；**首字符必须一致**；
  距离用 **OSA**（`modle → model` 是换位，普通 Levenshtein 距离是 2，会被阈值挡掉）；
  并列最优时**闭嘴**。
- **实测**：

  ```bash
  --modle   ⇒ 你是不是想用 --model？      --approvl ⇒ --approval
  --zzzzzz  ⇒ （不给建议，保持历史文案逐字不变）
  ```

- **踩到的一个真坑（已修正并变成判据）**：只按编辑距离时 `--work`（4 字符）会命中距离 1 的
  `--fork`——**猜错比不猜更糟**。加"首字符一致"后该类猜测整类消失，判据里留了这条具体反例。
- **架构约束**：已知旗标清单由**调用方注入**（`argParser` 传入），`flagSuggestion` 保持叶子模块。
  一开始让它自己 `import cliFlagTable`，架构门禁当场报"新增环"——白名单环①从 4 成员被撑到 5 成员。
  现已按本仓惯例**拆环而不是放宽白名单**，并加源码级判据防复发。
- **判据**：`tests/unit/flagSuggestion.test.ts` ①–⑥。

### F6. 每条 CLI 命令都先打一行 `node:sqlite` 实验性警告 —— **已修**

- **现象（客户视角就是"一启动就报错"）**：

  ```bash
  node dist/src/cli/exec.js doctor        # 或 session list / kv list --kv-adapter memory / …
  # (node:22004) ExperimentalWarning: SQLite is an experimental feature and might change at any time
  ```

- **根因**：`src/adapters/kv/sqliteKv.ts` 顶层 **值导入** `node:sqlite`，而 `src/adapters/index.ts`
  这条 barrel 把它**静态**带进 CLI 装配链（`cliServerCmds` → `adapters/index` → `sqliteKv`）。
- **这是一处"声明与实现不一致"**：同类文件 `sqliteStorage.ts` 早已是 `createRequire` 懒加载，
  而 `kvStoreFactory.ts` 的注释也写着"sqlite 后端**懒加载**"——**文档说了、代码没做**。
- **修复**：`SqliteKv.loadDatabaseSync()`（私有静态，与 `SqliteStorage` 同一口径）。
  实测：`doctor` / `session list` / 未知旗标路径的 stderr **不再含该警告**；
  真选 `--kv-adapter sqlite` 时仍可写可读（**懒加载不是删功能**）。
- **判据**：`tests/unit/sqliteLazyLoad.test.ts` ①（结构：`src/**` 不得值导入 `node:sqlite`）
  ②（实跑负对照：不碰 sqlite 的命令 stderr 必须干净）③（实跑正对照：sqlite KV 读写仍通）。
  结构 + 实跑两条腿，是因为"结构对 ≠ 行为对"。

### F7. `--help` / 无参数是一堵 100+ 行的旗标墙 —— **已修（分层，未删参考）**

- **现象**：`omniharness`（无参数）与 `--help` 打印**同一份**全量参考；第一次用的人要的只是"从哪开始"。
- **修复**：帮助顶部加**五行**「快速开始」（起工作台 / 跑一次任务 / 零额度试跑 / 环境诊断），
  文案仍在 `defaults/cliHelp.json`（改文案不改代码），参考手册原样留在下面，中间空行分隔。
- **判据**：`tests/unit/cliHelp.test.ts` ①（行数公式与分段位置）、⑦（段必须存在且够用；
  **段里出现的每个 `--flag` 都必须被 CLI 认识**——防"帮助漂了"）。

### F8. 中栏在 1000px 视口下横向溢出 —— **未修（如实登记）**

- **证据**（1280×820 与 1000×700 真机，两栏都展开时）：

  ```
  .col center    scrollWidth 447  >  clientWidth 319   （overflow-x: auto ⇒ 出现横向滚动条）
  .composer      scrollWidth 430  >  clientWidth 285
  ```

- **影响**：笔记本电脑（1280/1366 宽）+ 左右栏都展开时，输入区的模型/推理/发送控件会被推到视野外。
- **为什么本轮不修**：它不是"再挤一挤"能解决的——三栏固定宽度 + 输入条的单行布局在窄中栏下必然溢出，
  正确做法是给输入条做**断点重排**（窄栏时换行/收纳为一级菜单），而这是有独立视觉验收面的改动
  （`web/test/responsiveProbe.mjs` 覆盖 640px 档），应当单独一轮做并逐档截图核对，不应塞进本轮。
- **前置**：先定"窄栏时哪些控件降级"的产品口径，再动 CSS。

### F9. bundle 补丁层的告警反复打印且不可行动 —— **未修（如实登记）**

- **证据**：本工作区每次 CLI 调用都会在 stderr 打印
  `[omniharness] bundle 补丁层忽略非法配置项: k（来自 a-signed.json）`（实测多条），
  而这句话没告诉客户**怎么办**（哪个键合法？改了会怎样？）。
- **为什么本轮不修**：这是**真实配置问题**的告警（不是噪声），改成一句更有用的话需要先定义
  "合法键"的客户可见表达（很可能要配一个 `config keys` 之类的出口），属于独立的小特性而非文案调整。
- **前置**：确定合法配置键的对外开放查询方式。

## 四、诚实边界

- **本轮的"改善"都有像素或实跑读数撑着，但都不是两种条件下的对照实验**：F3 的宽度回收是同一台机器、
  同一份数据、同一段文本的前后测量（可信）；而"客户会不会因此少卡一次"没有任何用户数据支撑，
  **不得**把本文件当成转化率结论引用。
- **未修项 F8 / F9 是本文件的一部分**，不是遗漏：F8 需要独立一轮（含 640px 档视觉验收），
  F9 需要先定"合法配置键"的客户可见出口。把"我没做"写成"环境不允许"是最容易骗过自己的一类虚报。
- **F1–F3 的观感结论来自真机深色主题 + 1440/1280/1000 三档视口**。浅色主题**已复核**：真机注入
  `omni-theme=light` 后截图（侧栏标题+紧凑时间、空态示例卡、悬停覆盖层底色均正常），并跑了
  `web/test/visualProbe.mjs`（两主题 × 1280/640 两档，**42 张图存档于 `web/archive/`**）。
  **仍未逐屏复核的是**：640px 档的**真机**行为（探针的 640 档用桩数据）与浅色主题下的**真实悬停**
  覆盖层观感（底色取自行态变量、属性上跟随主题，但只核过静态图）。
- 本轮**没有**触碰"面向客户的对外材料"（README/官网口径），因此不涉及对外数字口径问题。
- **工程状态（本轮收尾实测，可复跑）**：`node scripts/runGates.mjs` 快层实跑 10/10 通过；
  `--tier=typed` 通过；全量单测 **3099 例 / 0 失败 / 4 跳过**；`npm run web:test` **374 例 / 0 失败**。
  本轮唯一一次红灯来自**架构门禁**（即 §二 F5 记的那条环），已按"拆环而不是放宽白名单"修掉并留源码级判据。
