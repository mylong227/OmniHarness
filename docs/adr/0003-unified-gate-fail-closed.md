# 0003 统一门禁：审批→沙箱→执行→记录，fail-closed

- 日期：2026-09-06
- 状态：已接受

## 背景

工具执行路径若散落多处、各自裁决，会出现「某条路径漏过审批直接跑危险命令」的纵深防御缺口。
审计曾发现工具层自身零防御、注释与实现不符的情况。需要把安全裁决收敛到单一、可验证的闸门。

## 决策

所有工具调用（含 MCP 桥接进来的远端工具）必经统一门禁 `ToolGate.gate()`：

1. **审批**：`ApprovalPort.decide` 裁决 allow/deny（含 plan 只读档）；
2. **沙箱**：`SandboxPort` 执行，危险命令 / 工作区外路径拦截；
3. **执行**：通过后才真正运行；
4. **记录**：结果写入审计日志（哈希链）。

fail-closed 原则：任一环节出错（审批端口抛错、配置缺失、裁决未知）一律 deny，绝不「默认放行」。
门禁在组合根统一装配，**绝不在 `StepRunner` 内部 `new` 适配器**（避免每个调用点自建门禁导致不一致）。

## 后果

- 正面：安全语义可一处验证；新增工具/接入点默认受保护。
- 负面：门禁装配点集中，需保证所有执行入口都接入（MCP server、code executor 等均已接入）。
- 替代方案：各工具自带校验（已证存在漏检，否决）。
