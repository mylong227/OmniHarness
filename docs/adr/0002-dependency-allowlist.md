# 0002 依赖准入制（allowlist + 四闸门自检）

- 日期：2026-09-06
- 状态：已接受

## 背景

项目早期奉行「零依赖」铁律，但部分能力（如本地语义检索）确需引入第三方库（如 `@huggingface/transformers`）。
完全禁止会阻碍能力演进；完全放开又回到供应链不可控的老路。需要一种既允许必要依赖、又强约束的机制。

## 决策

采用**准入制 + 分层隔离**：

- `dependency-allowlist.json` 登记每一个被允许的第三方包，条目须含五字段（名称 / 版本范围 / 许可 /
  用途 / 审批人），且仅接受 permissive 许可；
- `scripts/check.mjs` 提供四道闸门：零第三方裸导入、allowlist 完整性、许可合规、体量门禁；
- `src/ports/**` 与 `src/core/**` 恒保持第三方-free（不变量，由 CI 持续校验）；
- 既有零依赖自研实现（BM25 / RFC6455 / Ed25519 / N-API FFI / LCS diff）全部保留，不因引入依赖而删除。

## 后果

- 正面：在「可控」前提下允许能力升级；审计路径清晰（每个依赖可追溯到审批）。
- 负面：新增依赖需走登记流程，短期偏慢。
- 替代方案：纯零依赖（阻碍语义检索落地）/ 纯放开（供应链失控），均被否决。
