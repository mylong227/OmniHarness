# 0001 六边形架构：ports/adapters 分层 + 核心零第三方依赖

- 日期：2026-09-06
- 状态：已接受

## 背景

OmniHarness 融合 Codex Harness 与 DeepSeek Harness 的能力，代码量庞大（500+ TS 文件）。
若让核心逻辑直接依赖具体实现（某沙箱、某模型 SDK、某存储），会导致：测试困难、替换实现成本高、
供应链风险不可控。需要一种稳定的结构约束依赖方向。

## 决策

采用六边形（端口-适配器）架构：

- `src/ports/**` 定义纯接口（端口），**强制零第三方依赖**；
- `src/adapters/**` 提供具体实现（适配器），可依赖第三方，但须经准入；
- `src/core/**` 只依赖端口，不含具体实现；
- 组合根（`Container` / `RuntimeFactory`）在启动时直接 import 具体适配器完成接线，
  运行时核心代码不再 `new` 适配器。

`scripts/check.mjs` 以四闸门强制该约束（零运行时依赖 / 禁止第三方裸导入 / 文件名规范 / 体量门禁）。

## 后果

- 正面：可测试性高（端口可 mock）、实现可替换、依赖面可控。
- 负面：样板代码偏多（每个能力需 ports + adapters 两份）；新成员需先理解分层纪律。
- 替代方案：曾考虑「必要即可依赖」的宽松策略，但被供应链与可测试性要求否决，最终落定为
  「准入制 + 分层隔离」（见 ADR-0002）。
