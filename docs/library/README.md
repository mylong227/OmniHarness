## 0. 阅读契约（三条铁律）

**铁律一：只收能接到现有代码的理论。**
每一节必须回答：「这条理论对应本仓库哪个文件/哪个类？它改变了什么？验证它需要跑什么？」
接不上的理论不进本馆（可以进附录「远期观察」，但不占主线）。

**铁律二：每个类比必须标注成熟度等级（L0–L3）。**
本仓库有大量以物理/生物/化学命名的引擎（退火、免疫、涡环、QEC、结晶、对称破缺…）。命名不等于机制。本馆强制分级：

| 等级   | 名称       | 判据                                         | 例                                      |
| ------ | ---------- | -------------------------------------------- | --------------------------------------- |
| **L0** | 命名级     | 只有名字像，算法是普通启发式；换名不影响行为 | 大多「隐喻型」算子                      |
| **L1** | 结构同构   | 数据结构/组合律与理论对象同构，可等式推理    | `genesis/algebra.ts` 的 Cost 交换幺半群 |
| **L2** | 动力学同构 | 演化规则与理论方程同构（同一差分/微分形式）  | `heatEquationAnnealer.ts` 的扩散步      |
| **L3** | 可证性质   | 理论中的定理在本实现里被单测机械证明         | `genesis/regime.ts` 的单调收缩⇒不动点   |

**说 L3 必须是「有测试」**。没有测试的收敛性声明一律降级为 L1/L2。

**铁律三：隐喻不是罪，「把隐喻当物理」才是。**
例如 `genesis/ledger.ts` 的能量账本**不是**能量守恒（物理量），而是**记账不变量**（会计量）。它在数学上严格成立（record/commit 闭合），但不能引用热力学第一定律为它背书。本馆对这类边界逐条显式声明。

## 4. 全局映射总表（学科 → 代码 → 成熟度）

> 成熟度按铁律二分：**L0** = 命名级（诚实：目前只是启发式）；**L1–L3** = 有结构/动力学/定理支撑。
> 「现状」列是**今天代码的真实状态**，不是目标。

| 理论对象                     | 本仓库接口                                                         | 成熟度    | 现状一句话                                              |
| ---------------------------- | ------------------------------------------------------------------ | --------- | ------------------------------------------------------- |
| 交换幺半群 / 自由幺半群      | `genesis/algebra.ts`（`Monoid`/`Cost`/`vectorConcat`）             | **L3**    | 结合/单位/交换有单测，可组合推演                        |
| 函子定律（恒等/组合）        | `genesis/modalityPort.ts`（`Modality.map`）                        | **L3**    | map 双律有单测                                          |
| 指称语义 / 算子幺半群        | `genesis/operator.ts`（`composeOperator`/`identityOperator`）      | **L3**    | 纯函数 + 组合律有单测                                   |
| 记账不变量（非物理守恒）     | `genesis/ledger.ts`（record↔commit 闭合）                          | **L3**    | 守恒可机械检出；**勿引用热力学背书**                    |
| 单调收缩⇒不动点              | `genesis/regime.ts`（`prune`/`fuse`/`plan`）                       | **L3**    | 收敛性有单测；这是全库最强的理论兑现                    |

| 自然梯度 / Fisher 度量       | `adapters/belief/naturalGradientBelief.ts`                         | **L2**    | 用了自然梯度方向；流形假设未验证                        |
| 低秩最优逼近（Eckart–Young） | `context/lsaEngine.ts`                                             | **L1**    | SVD 分解存在；**实测叠加有害**（见 U3 实验）            |
| 谱图 / 幂迭代（PageRank）    | `context/codeReferenceGraph.ts`                                    | **L1**    | 44 万边实测**零增益**（稠密图收敛均匀）                 |
| 稀疏检索（BM25 词法）        | `search/bm25Index.ts`                                              | **L1**    | 主力召回；形态归并已破一层天花板（67%）                 |
| 免疫·阴性选择 / 危险理论     | `adapters/monitoring/immuneMonitor.ts`                             | **L0→L1** | 框架在；与 prompt injection 对抗（AgentDojo）**尚未接** |

| 自发对称破缺                 | `adapters/monitoring/symmetryBreakingEngine.ts`                    | **L0**    | 命名级；未定义序参量                                    |
| 拓扑荷守恒 / 涡环            | `adapters/spill/vortexRingPacket.ts`                               | **L0**    | 打包语义，非拓扑不变量                                  |
| 量子纠错码                   | `adapters/memory/qecEncoder.ts`                                    | **L0**    | 用冗余/校验思想；**非量子**，宜改称「纠删/校验码」      |
| 大尺度结构 / 共振同步        | `resonantFieldEngine`（U1 统一基板，含宇宙网）                     | **L0→L1** | 邻接/相似连通在；Kuramoto 同步动力学**未实现**          |
| 编辑与变异（CRISPR 隐喻）    | `adapters/skill/crisprSkillEditor.ts`                              | **L0**    | 技能改写；非基因编辑                                    |
| 进化·适应度地形              | `evolution/evolutionControllerImpl.ts` + `twistDiscoveryEngine.ts` | **L1**    | 闭环在；势函数是否真可验证看向下一条                    |
| 可验证奖励（RLVR）           | `evolution/verifiableReward.ts` + `rlvrController.ts`              | **L1**    | **本库最值得升到 L3 的方向**（编译/测试绿即奖励）       |
| Pass@k 与置信区间            | `eval/passK.ts` + `evals/`                                         | **L1**    | 已有 Pass@k；置信区间与 ≥5 次跑规范化待补               |
| 概念漂移 / 时间一致性        | `memoryAnnealing` 端口                                             | **L0**    | **A-TMA「ghost memory」风险无对策**（见 02 卷）         |

**读表法**：找 `L0` 最多的列 → 那是「隐喻税」最重的地方；找 `L3` 列 → 那是可以引以为据的护城河。**升级的最高 ROI 顺序不是补 L0，而是把 L1 升到 L3**（成本低、可信度跃升）。

## 5. 引用规范

- 外部来源一律在卷末「参考」列出，含 arXiv 编号 / DOI / 厂商博客，便于复核。
- 凡「厂商/社区自报」数字（如 Terminal-Bench 提升幅度），正文明确标注**自报**并提示需独立复现。
- 凡本项目实测数字，标注**实测**并给复跑入口（脚本路径）。
- 凡本文作者的推论，标注**推论**，与「来源结论」分开。

> 本馆会随项目演进修订。修订时**不删旧结论**，而是加「~~废弃~~ + 原因」，保留判断轨迹。
