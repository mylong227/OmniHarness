## 1. RLVR：可验证奖励强化学习

**核心**：不训偏好模型，直接用**环境可判定的结果**当奖励——编译通过 / 测试绿 / 类型检查过 / 数学答案对。代码任务天然适合，因为「代码能否通过测试」是自动判定、零人工标注的。

**2026 工程面进展**：

- 分布式 agentic RL 训练系统出现（如港大+阿里的 ROLLART：硬件亲和映射、轨迹级异步、状态感知计算，**自报** 3000+ 异构 GPU 上 1.35–2.05× 加速）。
- 多轮任务的长程规划训练（如中科大 Agent-R1 v2，**自报**）。

**已知致命坑（必须记账）**：RAGEN/StarPO 论文明载 **"Echo Trap"**——轨迹级 RL 会训崩/退化为自说自话。缓解需**轨迹过滤 + 批评者 + 梯度稳定**（StarPO-S）。

> **对本仓库的意义**：`src/evolution/` 已有 `verifiableReward.ts` + `rlvrController.ts` + `rlvrLoop.ts` + `inMemoryReplayBuffer.ts` + `failClosedEvolutionGate.ts`——**结构上已经对齐前沿**（尤其有 fail-closed 门禁，这比多数实现谨慎）。缺的是：
> ① 势函数的**覆盖率与可证伪性**（哪些任务真有 verifiable verdict？）；
> ② **Echo Trap 防护**是否有对应机制（回放缓冲的多样性过滤？）；
> ③ 是否有**同 corpus 的开关隔离 A/B**（本仓库记忆里已立铁律：增益须同 corpus 开关隔离——这条要继承到 RLVR 上）。

## 2. 记忆：从「被动检索」到「工具化决策」

**范式转变**：新一代框架不再让模型被动接收检索结果，而是**把记忆管理本身工具化**，让模型主动决定「**何时记、记什么、何时取**」。

- **AgeMem**（记忆工具化 + 决策回路）：用**三阶段渐进 RL + 分步 GRPO** 解决记忆操作的稀疏奖励问题；**自报**在五个长程任务基准上同时改善任务性能、记忆质量与上下文效率。
- **MemCon**：把记忆管理建模为**控制问题**，用 **UCB bandit** 自适应选择检索策略，**自报**六任务成功率最高 +15.2pp。

> **对本仓库的意义**：本仓库的检索策略选择目前是静态旋钮（`context/recallKnobs.ts`）。**MemCon 的思路可以极低成本落地**：把现有若干检索策略（纯 BM25 / 形态归并 / 混合）当作 bandit 臂，用历史任务成功与否作 reward，在线选择。**零新依赖**（UCB 是一行公式）。这是本馆认为**性价比最高的前沿移植点之一**。

### 2.1 关键陷阱：Ghost Memory（时间混淆）

**A-TMA 框架揭示的问题**：**过期事实与当前事实共存**。系统同时检索到「X 在 Y 文件」（三个月前）与「X 已移到 Z 文件」（上周），导致**时间混淆**。

> **对本仓库的意义（重要缺口）**：本仓库的 `resonantMemoryEngine` / `bm25Index` 是**纯相关性**检索，**没有时间维度**。`memoryAnnealing` 端口存在，但**是否真正做「时间衰减 / 事实失效」未验证**。
> 后果：项目重构（文件移动、改名）后，旧事实会与新事实一起被召回，**Agent 会依据过期事实行动**。这在「重构升级」期间是高概率事件。
> **建议**：记忆条目带**写入时间 + 失效条件**；检索分数 = 相关性 × 时间衰减 × 冲突消解（新事实胜出）。这是 T3 主线的核心。

## 3. 技能：粒度比数量重要（SkillsBench 实证）

**SkillsBench**（84 任务 / 11 领域）定量评估技能（`SKILL.md`）的真实效果，结论**反直觉且很有约束力**：

- **人工精编技能：通过率平均 +16.2pp**；
- **AI 自生成技能：无正增益**；
- **简洁、单一职责的技能收益最高**；
- **堆叠多个技能会引入上下文噪声**（负收益）。

> **本仓库必须遵守的三条硬约束（推论）**：
>
> 1. **不要靠「自动生成技能」来堆技能库**——实证无增益。
> 2. **技能必须单一职责**——这正好和 `CODE_STANDARD.md` 的「一个函数一个职责」同构，是全仓库一致的价值观。
> 3. **技能堆叠要有上界**——需要「技能选择的稀疏化」（与 §2 的 bandit 选择同一套机制）。
>    这条也和 §4 的「渐进式披露」互相印证：**技能不该全塞进系统提示**。

## 4. 推理：测试时计算 = 变分策略优化（理论桥）

**理论结果（Hashash et al. 2026）**：测试时花更多算力（搜索轨迹、分支、辩论）**等价于在新息（policy）空间做变分优化，最小化期望自由能 EFE**。这给「推理强度」一个理论解释，而不是调参玄学。

单步期望自由能分解（两个等价写法）：

```
G_τ(π) = Risk + Ambiguity
       = D_KL( q(o_τ|π) ‖ p(o_τ) )            # 风险：偏离目标先验
       + E_{q(s_τ)}[ H( p(o_τ|s_τ) ) ]        # 歧义：状态不确定性

等价地：
G_τ(π) = − EpistemicValue(信息增益，鼓励探索)
         − PragmaticValue(目标效用，鼓励达目标)
```

**实践映照**：MCTS / 过程奖励引导的 beam search，本质是在**认知探索**与**目标收敛**之间做权衡；更多测试时算力 = 先降低认知歧义，再承诺输出。

> **对本仓库的意义**：这为 `reasoning_effort` 提供了**可操作的解释**——
> 「加大推理强度」= 允许更多 EFE 下降步（更多候选、更多验证、更多回溯），代价是 token；
> 因此**推理强度预算应当是任务相关的**（难点多给，易点少给），而不是全局常数。
> **落地**：把 `reasoning_effort` 与「任务不确定度估计」挂钩（不确定度高 → 提升 effort），形成一个小闭环。这与 §8 的「推理预算重分配」（LangChain 实证）是同一件事的**理论与工程两面**。

## 5. 世界模型即程序（world-model-as-program）

**做法**：把世界模型写成**可运行、可验证的程序**，让 LLM 像物理学家一样做「假设—实验」循环，而不是生成自由文本。
**成绩（自报）**：某框架 + Claude Opus 4.8 在 ARC-AGI-3 公开集达 **98.98% RHAE**。
**诚实标注**：ARC Prize 主席认可该方法，但指出部分分数**依赖固定兜底规则**且**未经官方独立验证**。→ 视为「方向可信、数字待复核」。

> **对本仓库的意义**：本仓库的 harness 本身就是「程序化世界模型」的天然载体——`workflowRunner` 的 DAG、`graphStore` 的图、`eval` 的可判定断言，都可以作为「假设的可执行表达式」。
> **推论**：与其加一个「推理模块」，不如**让 DAG/断言成为显式推理载体**：agent 提出假设 → 编译成 DAG/断言 → 执行验证 → 采纳/丢弃。这是零新增依赖的路线。
