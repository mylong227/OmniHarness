>
> 判定口径（不做模糊处理）：每一项必须落在三类之一——
> **① 已落地**（有提交 + 可证伪判据）、**② 阻塞**（缺外部条件，写明缺什么、缺它为什么做不了）、

## 二、F2 的 Web 工作台 tab：为什么标"部分"而不是"已落地"

F2 的判据原文是「治理台展示的**每条晋升记录**都能用 `audit verify` **独立复核**（数据与证据同源）」——
这条判据**已在数据面成立且有判据钉死**（`PromotionHistoryService` + `evolution history`，含三类篡改变异自证）。

未做的部分是**前端可视化**（Web 工作台新 tab）。诚实标注的理由：

- 它是**产品面**工作（渲染、交互、一键回滚按钮的确认流程），不影响上述判据的成立；
- 前端的正确做法是消费**同一个**服务（`PromotionHistoryService.view()` 已给出 `rows/summary/rollbackTargets`），
  现在做与日后做不会产生返工——**数据契约是稳定的**。

## 三、这份裁决如何被复核

- 每一项的"已落地"都能追到提交号，且提交里带**可证伪判据**（`node --test` 可直接跑）；
- "阻塞"项写明了**缺什么**（`wasmtime` 准入 / 两关显著），并说明在此之前系统**如何诚实降级**
  （wasm 档 fail-closed 拒绝、进化保持默认关）；
- "非代码项"写明了**若要做的前置**，避免下一个人把"商业决策"当成"没写代码"。

> 反泡沫续期（沿商业化报告 §5 的"不做"清单）：**本仓不发布未经两关验证的增益数字**；
> 对外材料引用探针结论时必须带上"机制级、夹具对机制友好、不能外推为生产增益"的边界。

## 四、本轮复核改正的一处登记（自我纠错）

`Wave C 的 evolved 档 / J8` 最初被登记为「**阻塞：缺 `wasmtime` / Rust 工具链**」。后续复核发现**不准确**：

本机实测：

```
cargo 1.98.1 (797e8a9bc 2026-08-05)      rustc 1.98.1 (48a229cea 2026-09-01)
rustup target list --installed → wasm32-unknown-unknown（已安装）
crates/ → omni-cli / omni-core / omni-napi / omni-sdk / omni-sdk-gen / omni-wasm
```

⇒ **构建工具链齐备**，wasm32 目标也能编译。真正的缺口是**运行时行为**：

- 要在**不可信代码**上强制三件事：① 默认拒绝全部 import；② 超时**就地中止**
  （V8 无 fuel 计量，`WebAssembly` 一旦进入无限循环，宿主线程打不断它）；③ 内存硬上限。
- 可行的**零新依赖**路径：Node 内置 `WebAssembly` + **Worker 线程**（`resourceLimits` 限内存、
  硬超时后 `worker.terminate()` 才是真中止）⇒ **不需要 `wasmtime`**，也就不需要依赖准入评审。

改正后的状态：**② 可做，未做**（而非"阻塞"）。这处改正与判据文化同源：
**把"我没做"写成"环境不允许"是最容易骗过自己的一类虚报**——它让后来每个人都绕道走。
