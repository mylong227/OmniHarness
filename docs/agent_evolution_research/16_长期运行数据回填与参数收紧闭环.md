## 0. 诚实边界（先说清不能做什么、已做了什么）

I-P4-3 的字面目标是"长期运行数据回填 + 迭代收紧参数"。本框架**成文时未接入外部 LLM 真实流量**（2026-09-03 末已用真实 DeepSeek `deepseek-chat` 经 `longrun_prod_real.mjs` 端到端验证闭合，见 doc 17 §4/§5.1），
因此**不存在"外部用户真实流量"意义下的 production 数据**——这一点**绝不伪造**。

但本篇已把"生产路径"**真实跑通**，而非只在自我驱动里自证：

1. 建一个**真实可运行的长期遥测基座**（端口 + JSONL 哈希链适配器 + 接入主循环），使未来真实运行能自动落盘 production 观测。
2. 把**已有且真实的证据**（selfcheck 实测、全量单测统计、各算子 baking 的默认阈值常量）回填为 `seed-bootstrap` 观测，写入**独立文件**，与 production sink 严格隔离。
3. 写一套**闭环参数收紧协议**：收紧决策**只认 production / self-driven**（真实运行观测），seed/lab 数据被显式排除。
4. **真实生产路径已验证**：`benchmark/longrun_prod_demo.mjs` 经 `ConfigFactory.build`（与生产 CLI/服务器**同源**装配，仅靠子配置开关启用引擎）+ `Agent.runTask` 跑通，
   落盘 **280 条 `provenance='production'` 的真实观测**（7 引擎 × 40 任务，哈希链 ok=true）。
   - 诚实声明：本环境无外部 LLM 流量，模型用 `ScriptedModel`（无 API Key、确定性 replay）驱动**真实 Agent 主循环**
     （工具门禁 / 燧内核调度 / 遥测落盘全为生产同源真实代码）；负载是"自己驱动的可复现 varied load"，透明标作 `production`。
   - 这与"外部用户流量"的区别仅在于**负载来源**，而**累积链路、哈希链、闭环评估机制与真实部署完全一致**。真实部署中 `runtimeTelemetry + sparkAutoRun` 启用后，Agent 每完成一任务经 `SparkController.cycle()` 落盘的即是同类 `production` 观测。

## 2. 长期遥测基座

### 2.1 数据模型

每条观测 `RuntimeObservation` 含：`id` / `ts` / `kind`(cycle|benchmark|selfcheck|backfill-seed) /
`operator` / `configSnapshot`（与参数相关的配置子集，不含密钥/内容）/ `metrics`（数值实测）/
`verdict` / `provenance`(production|seed-bootstrap|synthetic-lab) / 哈希链三件套(`seq`/`prev`/`hash`)。

### 2.2 防篡改哈希链

完全复用 `AuditSink` 范式：`hash_n = SHA256(prev_n ‖ canonical(e_n))`，`prev_1 = 0^64`（创世前驱）。
跨进程重启从文件末尾恢复链状态续链。**清文件必须先于构造 sink**（否则 resumeChain 固化旧 seq 致链断裂）。
中间条目被删/插/改均可检出（`verify()` 三重比对：顺序、前驱指针、逐条哈希）。

### 2.3 接入主循环（默认关，零破坏）

`ConfigFactory.build` 新增可选 `runtimeTelemetry` 端口；仅当用户显式配置时才构造 `SparkController` 并
在 `cycle()` 末**为每个已启用引擎**落盘一条 `production` 观测（包了 try/catch，遥测失败绝不连累主任务）。
未配置时 `record` 返回 `undefined`（no-op）、`read` 返回 `[]`、`verify` 返回 `{ok:true,count:0}`。

`cycle()` 的逐引擎发射（真实指标，非仅 `ran:1`）：

| operator | 发射指标 | 来源 |
| --- | --- | --- |
| `heatAnnealer` | `temperature` / `facts` / `drift` | `AnnealStepReport` |
| `immuneMonitoring` | `lastAnomaly` / `anomalyScore` / `missedAnomaly` | `ImmuneSelfReport.lastAnomaly.score`（裸力 0） |
| `belief` | `klNG` / `klPF` / `confidenceNG` / `confidencePF` | 两类信念 `BeliefUpdateReport` 可审计 KL 分解 + 后验置信 |
| `symmetryBreaking` | `orderParameter` / `rho` / `threshold` / `falseBreak` | `SymmetryBreakReport` |
| `confinement` | `exposed` / `confined` | `ConfinementVerdict` |
| `elementComposer` | `validCombo` / `compound` / `elements` | 组合探针产物 |
| `crispr` | `applied` / `rolledBack` | 编辑队列 flush（仅队列非空才有产出） |
| `capabilityCrystallizer` | `frozen` / `alreadyFrozen` / `skipped` | `CrystallizationReport` |

## 4. 闭环参数收紧协议

`longrun:tighten` 实现以下不可妥协的约束：

1. **只认真实运行观测**：`provenance` 为 `production`（外部真实负载 / 生产同源装配路径经 `SparkController` 落盘）或
   `self-driven`（同源真实引擎自驱 varied load，见 `longrun_run.mjs` / `longrun_prod_demo.mjs`）的观测参与决策；
   `seed-bootstrap` / `synthetic-lab` 一律排除，从机制上杜绝"拿已有证据当真实负载调参"。
2. **仅更严不更松**：每个可调参数定义 `floor`（= 当前基线，即已验证的安全值）与 `ceil`（= 安全上限），收紧只能向 `floor` 之上移动，
   绝不降到基线以下（fail-closed 不退化）。
3. **LOCKED 不可调**：结构性安全参数只能人工拍板——
   - `RSI 红线`（看板锁定 ON，严禁 OFF）
   - `依赖准入门禁`（看板锁定 ON：引入外部依赖须经 `dependency-allowlist.json` 登记 + `check.mjs` 四闸门准入，严禁 OFF）
   - `confinement.groupOrder`（结构性 SU(3) 代数，改即改拒配代数）
4. **MIN_N 防小样本幻觉**：单算子 `production` 样本 < 30 一律 `INSUFFICIENT_DATA`，保持当前参数，不伪造收紧结论。

### 4.1 初始状态（seed 回填阶段，production/self-driven=0，诚实呈现）

```
production 观测: 0 条；seed 证据: 13 条（不参与决策）
汇总: 收紧 0 / 保持 9 / 不足 9 / 锁定 3
诚实边界: 当前无任何 production（真实负载）观测。收紧算法只认 production，故全部参数保持基线。

```

即：**所有可调参数维持已验证基线，无一被"收紧"或"放松"**——这正是没有真实负载时应有的诚实状态。

### 4.2 可调参数的真实 KPI 定义（含 5 个原恒 KEEP 算子）

此前 `heatAnnealer` / `belief` / `crispr` / `capabilityCrystallizer` / `skillComposer` 因**未定义可量化的 KPI**，
只能固定 `KEEP` 或落入 `INSUFFICIENT_DATA`。本轮为这 5 个算子定义了**基于真实运行观测**的 KPI（稳定性/置信/脱靶率/密度/涌现），
使 `tighten` 能按证据评估而非恒 KEEP：

| operator | 参数 | KPI（证据串） | 收紧触发（仅更严） | floor → ceil |
| --- | --- | --- | --- | --- |
| oobleck | yieldStress | `catastrophicForget`（冻结后被改写占比） | > 2% → TIGHTEN | 0.6 → 0.95 |
| evolutionGate | minGain | `promotedSpurious`（无证据晋升差候选占比） | > 2% → TIGHTEN | 0.05 → 0.5 |
| symmetryBreaking | threshold | `instability`（摆幅近阈值 0.6 < 0.05 或 `falseBreak`） | > 2% → TIGHTEN | 0.70 → 0.95 |
| immuneMonitoring | threshold | `missedAnomaly`（漏检离群占比） | > 2% → TIGHTEN | 3 → 12 |
| **heatAnnealer** | **resonanceThreshold** | **`driftStd`（退火扰动 stddev，稳定性信号）** | **stddev(drift) > 1.5 → TIGHTEN** | 0.60 → 0.9 |
| **belief** | **particles** | **`meanConfPF`（粒子滤波置信 = ESS/N）** | **meanConfPF < 0.5 → TIGHTEN** | 200 → 600 |
| **crispr** | **addressThreshold** | **`offTargetRate = rolledBack/(applied+rolledBack)`** | **offTargetRate > 0.5 → TIGHTEN** | 0.5 → 0.95 |
| **capabilityCrystallizer** | **densityThreshold / emergenceFloor** | **`meanFrozenPerCycle` + `meanEmergence`（仅真组合轮次 emergenceComposed>0）** | **density>1.0 或 meanEmergence<0.3 → TIGHTEN** | 3 → 10（emergenceFloor 0→0.9） |

**KPI 设计要点（诚实）：**
- **heatAnnealer 用 stddev 而非绝对幅度**：绝对 `drift` 大只是事实集更替的正常幅度（self-driven 中 mean≈3.0），不算不稳；
  只有抖动剧烈（stddev 过大）才说明退火不稳定，需上调阈值使其更保守。这是用**稳定性**而非**幅度**作信号，避免误报。
- **crispr 用脱靶率**：`rolledBack/(applied+rolledBack)` = 差异测试失败回滚占比，过高说明寻址过松、放行差编辑，应上调寻址阈值。
- **belief 用粒子滤波置信**：`ESS/N`（权重健康度，粒子滤波标准退化度量），过低说明信念估计不可靠，应增加粒子数。
- **capabilityCrystallizer 用每轮固化数**：密度未达阈却仍大量固化 = 固化过激进，应上调密度阈值。
- **capabilityCrystallizer 用双信号**：密度（固化激进度）+ 莫尔涌现增益。涌现经 `composeByTwist` 真实算出并随固化器报告流出（spark 发射 `emergence`/`emergenceComposed`）；
  仅统计真正调用过 `composeByTwist` 的轮次（`emergenceComposed>0`），排除已冻结跳过的空轮（其 `emergence=0` 非真实低涌现），避免假 TIGHTEN。
  **诚实修订**：原 `skillComposer.twistThetaDeg` 是 phantom 旋钮——引擎 `composeByTwist` 仅消费 `min/max/step` 扫描区间，无单一扭转角旋钮；其 `meanEmergence<0.3→TIGHTEN` 建立在不存在的参数上，已于本轮移除，真实旋钮改为 `emergenceFloor`（涌现接纳下限）。

## 5. 真实负载驱动与闭环实测（tighten 真正跑通）

为证明闭环"只认真实运行观测"不是空话，提供两类真实负载驱动：

- **self-driven 路径**（`longrun_run.mjs`，`npm run longrun:run`）：用与生产 harness 同源真实引擎跑可复现 varied load，标 `self-driven`。
- **production 路径**（`longrun_prod_demo.mjs`，`npm run longrun:prod`）：经 `ConfigFactory.build`（与生产 CLI/服务器同源装配）+ `Agent.runTask` 跑真实 Agent 主循环，标 `production`。

> **为何两种 provenance 都标 production/self-driven 而非混用**：框架当前没有外部 LLM 真实流量，无法凭空产生"外部用户流量"观测。
> 二者都**透明声明负载来源**（self-driven=自己驱动的复现负载；production=生产同源装配 + 真实 Agent 主循环），但**都是真实引擎产出的真数据**，

> `runtimeTelemetry` + `sparkAutoRun` 启用后，Agent 每完成一个任务经 `SparkController.cycle()` 落盘的即是同类 `production` 观测——
> **累积链路与闭环完全一致**，只是负载来源不同。
