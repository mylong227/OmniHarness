# 19 · 太初数学内核（Genesis Core）—— 可推演 · 自适应 · 多模态

> 承接 `18`（自研化最低能耗方案研究报告）。本报告所述"整体全新且能力强大"的演进，不是功能堆砌，而是落地一个**统一数学内核（Genesis Core）**，把能耗计量、算子语义、多模态、自适应收敛全部提升为可推演的代数结构。代码位于 `src/genesis/`，已通过 17 项定律测试。

## 0. 设计哲学（反堆砌）

- **一个统一内核，而非一堆独立功能**：所有能力都落入同一代数（交换幺半群 + 指称语义 + 函子 + 收敛映射），彼此可组合、可推理。
- **数学可证**：每个核心性质都有对应单元测试机械证明（结合律 / 单位元 / 交换律 / 函子定律 / 守恒律 / 收敛性）。
- **零新依赖**：全部 `src/genesis/` 为纯 TS、零运行时依赖，符合铁律。
- **既有的九个仿生算子**（heatAnnealer / immuneMonitoring / symmetryBreaking / capabilityCrystallizer …）无需重写——它们均可包装为 `Operator<HarnessState>` 落入同一代数，作为 lawful morphism 接入。

## 1. 代数骨架 `algebra.ts`

| 结构 | 数学性质 | 工程意义 |
|---|---|---|
| `Cost`（tokens × joules） | **交换幺半群** | 资源计量满足结合律+交换律+单位元，组合顺序无关 |
| `vectorConcat` | 自由交换幺半群 | 多维资源（算力/存储/网络）统一计量 |
| `Monoid<A>` 接口 | 泛型半群/幺半群 | 后续结构复用同一抽象 |

> 注：`joules` 为估算代理值（每 token 经验系数），真实硬件需实测；关键不在物理精度，而在代数结构的严格成立，用于守恒律推演。

## 2. 多模态 `modality.ts`

- `Modality<A>` 作为**函子**：`map` 满足恒等律 / 组合律。
- `encodeText` / `encodeImage`：零依赖、可离线的**真实可计算特征**（文本 n-gram 包；图像亮度均值/方差/字节香农熵/宽高比）。
- `fuseModality`：按 `(kind, 特征签名)` 规范排序 ⇒ **交换律**严格成立（fuse(a,b) ≡ fuse(b,a)）。
- `alignModality`：跨模态余弦相似度 ⇒ 文本与图像可在同一向量空间比较/检索。
- 视觉语义编码器（CLIP 类）可作为 drop-in 适配器替换 `imageFeatures`，**代数不变** ⇒ 架构适应力强。

## 3. 算子指称语义 `operator.ts`

`Operator<S> = (state) => { next, cost, events }` —— **纯函数**，故：
- 无隐藏副作用，可等式推理；
- `composeOperator` 构成**幺半群**（结合律 + 单位元 `identityOperator`）；
- 成本经 `Cost` 幺半群累加，与组合顺序无关。
- 既有九个算子可 `liftOperator` / `liftCosted` 接入，无需重写。

## 4. 能量守恒账本 `ledger.ts`

双列记账不变量：**记录（record）必须最终结算（commit）**。闭合周期 `pending===0 且 recorded===committed` ⇒ 守恒。
- 任意"产生成本却忘记结算"的遗漏 ⇒ `isConserved()` 立即为假，可机械检出。
- 这是 Landauer / Toyabe（信息换能量）原理在软件层的落地：不可解释的能量泄漏被显式暴露。

## 5. 自适应元控制器 `regime.ts`

`plan: Regime -> Operator<GenesisState>` 为**纯函数**，故可等式推理。数学收敛性（可推演）：
- 熵为模态种类的**派生量**（香农熵）；
- 基本算子只做严格"收缩"：`fuse`（模态数 ≥3 → 合并，严格减少）、`prune`（成本压力 >0.7 → 丢弃最低优先级模态，减少）；
- 二者均只减不增，模态数有下界（≥1）⇒ 反复应用必在有限步到达**不动点**（长度不再变化 ⇒ plan 退化为恒等）。
- 这是对"自适应收敛"的**可证明保证**，而非启发式承诺。冷却（退火）等价于"通过融合冗余模态降低熵"。
