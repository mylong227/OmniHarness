## 0. TL;DR

1. **外部世界正在收敛到本仓的立场**：harness 本身是优化目标。Meta-Harness（37.6%，超过 Goose 的
   35.5%）、Co-Harness（harness 与模型联合后训练）、ShinkaEvolve 直接"进化出 agentic harness"、
   OpenAI "Harness Engineering"（2026-02）与 Cursor（2026-04）都把 harness 当一等优化对象——
   本仓过去数月的工程路线（门禁/守卫/判据）被外部验证为正确战场。
2. **但没有任何一家把「进化」和「治理」装在一起**。DGM / OpenEvolve / ShinkaEvolve 是研究器
   （无审计、无回滚、无权限、无 fail-closed）；AgentEvolver 是 RL 权重训练器（GPU，改模型——本仓
   反泡沫红线内不做）；AWM / ExpeL 是经验注入（无晋升门禁）。**治理化自进化仍是空位**——
   这是本仓的差异化，不是需要补的短板。
3. **自研方案（进化环 2.0，代号 GEE：Governed Experience Evolution）**：进化对象锁定三层
   **声明式资产**（技能 instructions / 洞见卡 / 工作流模板），全部走已有技能注册表与 fail-closed
   晋升门禁；评估采用 DSPy 式 train/val/test 纪律 + 本仓两关统计；外部只借四个机制
   （双源信号归纳、MAP-Elites 覆盖分桶、级联评估、经验回填），其余明确拒绝（§4 差异表）。
4. **明确拒绝清单**：代码自修改（DGM 主路径）、RL 权重训练（AgentEvolver）、MCTS 工作流图搜索
   （AFlow）、外部向量库/图库（全部）、verifier 委员会当完成判据——逐条理由见 §2/§3。

## 2. 机制级择优学习表（按六环组织）

> 判定口径：**采纳**（机制与约束直接相容）/ **改造采纳**（借思想、换实现以满足零依赖/审计/判据纪律）/
> **拒绝**（与本仓铁律或反泡沫清单冲突）。每条给出理由——"不照搬"必须说清为什么不搬。

### 2.1 信号采集环（本仓现状：孤儿模块，最弱一环）

| 外部机制                       | 来源                                    | 判定                          | 对本仓的具体落法与理由                                                                                                                                                                                                                                                                                                                |
| ------------------------------ | --------------------------------------- | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 成功/失败**双源**轨迹归纳      | ExpeL                                   | **采纳改造**                  | `failurePatternMiner.ts` 上产线（E1）只补了失败半边；AWM/ExpeL 证明**成功轨迹的归纳**同样是资产。落法：遥测行喂两个蒸馏器——失败→改进提案（已有），成功→**工作流/技能候选**（新增 distiller，走 memory M3 信任档纪律：工具输出默认不蒸馏，显式开启才入库）。理由：双源信号覆盖"做对了什么"与"做错了什么"，且全部为声明式资产，不改代码 |
| 从轨迹**归纳工作流**（非代码） | AWM                                     | **采纳改造**                  | 归纳产物落成 **workflow 模板**（`src/autonomy/graphStore.ts` 已有 DAG 存储）而非 AFlow 式自由代码。理由：保留 AWM 的"经验变资产"，但模板是声明式、可审计、可回滚的——这正是 AFlow 被拒的反面                                                                                                                                           |
| 自动课程（自出任务）           | Voyager / AgentEvolver self-questioning | **改造采纳（opt-in 探针档）** | 进化器自生成"自测任务"喂评估集——但必须过两关统计，不显著即判死。理由：自出题是样本效率杠杆（ShinkaEvolve 用更少评估拿更好结果的核心思想之一），但自证循环风险高（综述明确警告无外部反馈的精炼会掉分），故只作 opt-in 实验档，默认关                                                                                                   |

### 2.2 提案生成环

| 外部机制                                | 来源                      | 判定                                                                                                           | 理由与落法                                                                                                                                                                                                                                                                                                                       |
| --------------------------------------- | ------------------------- | -------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 改自身代码 + archive 开放式探索         | DGM                       | **拆开处理**：archive 思想**采纳**（候选池=技能变体档案，`twistDiscoveryEngine` 已有雏形）；代码自修改**拒绝** | 拒绝理由：① 代码产物绕过审计链（晋升的是"一段能跑的 Python"，不是声明式资产）；② 评估产物是 benchmark 分数，与本仓"两关+诚实"纪律冲突（SWE-bench 数字不可复现的老坑）；③ 安全红线（自改执行体=自我提权风险）。本仓 archive 存的是**技能变体**，变异算子是莫尔组合+LLM 改写 instructions（`rlvrLoop` 采样器已支持）               |

## 3. 分类法对位（arXiv:2508.07407：what / when / how）

| 维度              | 学术选项                                            | 本仓选择                                                                                       | 为什么                                                                                                                            |
| ----------------- | --------------------------------------------------- | ---------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| **what 进化什么** | 模型权重 / 提示 / 记忆 / 工具 / 工作流 / agent 代码 | **三层声明式资产**：技能 instructions、洞见卡、工作流模板                                      | 权重=GPU RL（反泡沫）；agent 代码=绕过审计（DGM 教训）；声明式资产可 diff、可审计、可回滚，且复用同一注册表与门禁（不造三套系统） |
| **when 何时进化** | online 持续 / offline 批量 / 触发式                 | **任务末触发**（spark/evolution cycle 已挂）+ **定期离线归纳**（`routineScheduler` cron 已有） | 两个挂点全是现成零件，新增为零；online 持续进化在无人类监督时不满足 fail-closed                                                   |
| **how 如何进化**  | 梯度（SFT/RL）/ in-context / 结构编辑               | **全部非梯度**：in-context 注入（技能检索）+ 声明式编辑（CRISPR/固化器）+ 门禁晋升             | 与零依赖、单人维护、审计要求一致；外部证据（ExpeL/Voyager/AWM 全部零梯度路线有效）也支持                                          |

三个维度上本仓选择**全部自洽且有外部佐证**——调研的价值是确认方向，不是改变方向。

## 4. 自研方案：进化环 2.0（GEE：Governed Experience Evolution）

### 4.1 与先行工作的正面差异声明（"不照搬"的工程表述）

| 维度     | DGM / OpenEvolve / ShinkaEvolve | AgentEvolver | AWM / ExpeL            | **GEE（本仓）**                               |
| -------- | ------------------------------- | ------------ | ---------------------- | --------------------------------------------- |
| 进化对象 | agent 自身代码                  | 模型权重     | 记忆注入（无晋升语义） | 三层声明式资产（技能/洞见/工作流模板）        |
| 评估     | benchmark 分数                  | RL 奖励      | 无（直接注入）         | 用户 verifyCommand + 两关统计 + val/test 纪律 |
| 晋升     | 分数达线即入 archive            | 训练收敛     | 无                     | fail-closed 门禁（多样性+退火+覆盖率分桶）    |
| 治理     | 无                              | 无           | 无                     | **审计哈希链 + 晋升审批 + 一键回滚（独有）**  |
| 基础设施 | 独立研究栈                      | GPU 集群     | 附加框架               | 零新依赖，全部长在本仓现有端口上              |

### 4.2 六环 → 模块映射（已有 / 新增 / 接线，不引入任何新系统）

```
信号   遥测行 ─┬─ 失败蒸馏器 failurePatternMiner（已有→E1 接线）
               └─ 成功蒸馏器 trajectoryDistiller（新增，改造 AWM/ExpeL；走 M3 信任档）
提案   twistDiscoveryEngine（已有）+ rlvrLoop 采样器（已有）
       + 经验回填字段（ShinkaEvolve 式，E3 接线）
评估   级联：静态检查 → verifyCommand（E4 自动推导，快→慢排序）
       → 两关统计 + val/test 纪律（E2 探针内置 DSPy 纪律闸）
晋升   failClosedEvolutionGate + promotionAdmission（已有）
       + rewardCoverageMeter 升格为按工况分桶（MAP-Elites 式，纯函数新增）
应用   skillRegistry.replace（已接线）+ 工作流模板落 graphStore（新增小件）
治理   evolution.promoted 审计行（已有）+ 晋升级快照/还原（E5）+ 治理台（商业报告 F2）
```

**三层资产统一原则**：洞见卡与工作流模板都注册进 `SkillRegistry`（洞见=特殊技能类型，
模板=带参数的工作流技能），共享检索、稀疏化、门禁、审计——**不造三套生命周期**。
这是与 AWM（独立记忆）+ ExpeL（独立 insight 库）最大的结构差异，理由是单人维护的表面积控制。

### 4.3 实施判据（对商业报告 E1–E5 的细化与修正）

| #       | 项         | 本篇修正/细化                                                                              | 可证伪判据（离线）                                                                                                                            |

工作量口径：E1+ ≈4–6 人日、E2+ ≈5–7、E3+ ≈3–4、E4+ ≈3–5、E5 ≈2–3、N1 ≈2–3、N2 ≈1–2；
依赖关系：N1/N2 依赖 E1+（有候选池才有分桶对象）；全部依赖已落地的 G1/G3 守卫。

### 4.4 风险（进化环 2.0 特有）

- **归纳噪声**：LLM 蒸馏出的技能/洞见可能错误或平庸 ⇒ 两关统计判死 + 技能稀疏化控预算 +
  门禁 fail-closed（三重已有防线，新防线为零——这是设计目标）。
- **自出题自证循环**（Voyager/AgentEvolver 借来的一半）：自动课程默认关，仅 opt-in 探针档，
  证据标准同 E2（两关）——综述与 §3.9（无外部反馈精炼掉分）都亮过红牌。
- **三层资产表面积**：坚持统一注册表，若实现中发现类型系统撑不住（技能 schema 差异过大），
  退回"只做技能+洞见"两层，工作流模板推迟——**减法优先于完整性**。

## 5. 诚实清单（本报告的未验证假设）

- 星标数、跑分（SWE-bench 20→50%、Meta-Harness 37.6%、AFlow 4.5% 成本等）均为**检索快照**，
  未复现；归档研究已证外部"头条数字"大面积不可复现，本报告引用它们只为方向判断。
- GEE 方案**未实现、未测量**——本文只给设计与判据；E1+/E2+/N1 落地并出数前，
  对外不得声称"治理化自进化已实现"。
- 双源信号（成功侧归纳）的增益假设未验证：AWM/ExpeL 的证据来自 WebArena/Mind2Web（web agent 域），
  向编码/通用任务域外推是假设。
- 本报告与 `archive/agent_evolution_research/`（历史快照）口径独立；若数字冲突，以本机可复跑判据为准。
