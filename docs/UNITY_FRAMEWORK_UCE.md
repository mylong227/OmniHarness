# OmniHarness 万法归一架构（UCE）

> 副题：**万物归一 · 万物守恒 · 万物演变**
> 编制：2026-09-05 | 性质：**第一性框架设计（待实施）**，非已落地声明
> 立场：本文**取代**"焊接式 RDAA"思路。焊接 = N 模块拼 N-1 个同步边界 + N 条验证路径，边界处必漏（后遗症）。UCE = 先立唯一基质、唯一守恒律、唯一演变机制，能力从中涌现，由构造保证一致性，无边界、无后遗症。

---

## 0. 一句话定义

> **把代码、记忆、工具、智能体、任务、消息，全部还原为「同一个共振场里的节点」；用一条「认知能量守恒律」约束一切状态变迁；让场在「可验证奖励」这个势函数下自发演变。**
> 上下文、检索、eval、互操作、自改进——不是六个模块，是**同一个场在不同视角下的切面**。

---

## 1. 三条第一性公理（不可再分）

| 公理 | 名称     | 内容                                                                                       | 计算落地形态（不玄学）                                                                                          |
| ---- | -------- | ------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| Ⅰ    | **归一** | 一切皆是共振场中的节点，拥有唯一「共振地址」。无例外、无平行表示。                         | `Node = (resonanceAddr, payload, edges)`；payload 可为 AST 片段 / 记忆 / 工具 schema / agent spec / 任务 / 消息 |
| Ⅱ    | **守恒** | 存在守恒量 **C（认知能量 = 注意力配额 + 信用）**，在场内流转、不增不减；任一变迁必须入账。 | 账本 = 既有审计哈希链（seq/prev/hash）；C 的增量由 QEC 综合征检测校验                                           |
| Ⅲ    | **演变** | 场在守恒约束下、以「可验证奖励」为势函数自发形变/涌现新节点，无外部硬编码规则。            | 势函数 = 执行环境 verdict（编译/测试绿，零标注）；演化算子由 evolution 闭环驱动                                 |

**为什么这三条就够了**：归一消除"多套表示"→ 无状态分裂；守恒消除"账算不清"→ 无丢失/伪造；演变消除"写死规则"→ 自适应。三者闭合，构成不可再约的最小框架。

## 2. 基质：共振场（Resonant Field）

### 2.1 统一表示

```
Node := { addr: ResAddr,        // 结构哈希(确定性)+局部拓扑编码
          kind: code|memory|tool|agent|task|msg,
          payload: Any,
          edges: ResAddr[] }     // 共振邻接，非字符串引用
```

- **共振地址 `ResAddr`**：对节点 payload 计算结构哈希（可复现、无随机），再叠加上下游子图的局部拓扑编码。同类节点因结构相似而天然聚簇。
- **检索 = 共振匹配**：给定 prompt，算其 `ResAddr`，在场上做邻接共振，命中即召回。**不是 BM25/PageRank 这种外挂排序，是场的内禀几何**。

### 2.2 这顺手消灭了 repo-map 缺口

Aider 的 repo-map 是「AST 图 + PageRank 排序」——仍是**图上的外挂检索**。UCE 里，AST 符号从一开始就是场的节点，结构关系就是 `edges`。**图上下文是场的内禀属性，不是叠加层** → 不存在"BM25 之上再焊一层"的边界，自然无后遗症。

### 2.3 场即上下文、即记忆、即工具、即智能体

因为都是同一种 `Node`，以下全部是同一份数据的不同 `kind` 与不同切面：

- 上下文窗口 = 场的「当前激活子图」
- 长期记忆 = 场的「持久化节点子集」
- 工具 = `kind=tool` 的节点，调用 = 在场上发起一次能量流转
- 子智能体 = 场的「受限子图视图」（沿用现有 Subagent 隔离，但现在是同一场的局部投影，而非另起进程语义）

## 3. 守恒律：认知能量账本

### 3.1 守恒量 C

```
C_total = Σ attention_quota + Σ credit
ΔC = 0  (任何变迁必须入账；信用可正可负，失败扣分)
```

- **账本 = 审计哈希链**：把既有 `AuditSink`（seq/prev/hash 三重篡改检出）**升格为守恒账本**。每一笔 token 消耗、每一次工具调用、每一轮信用增减，都作为一条不可篡改的账。这复用已落地能力，不是新造。
- **QEC = 守恒的纠错层**：若某条轨迹出现「能量不守恒」（凭空多 token、信用跳变、账本哈希链断裂），即判为**综合征 (syndrome)**。

### 3.2 这顺手消灭了 eval 缺口 + 后遗症

传统 eval：另起一套 SWE-bench 跑分流水线，与运行时验证分裂（两条验证路径 = 后遗症源）。
UCE 里：**eval = 守恒校验**。一次任务跑完，账本闭合且零综合征 ⇒ 成功；出现综合征 ⇒ 早停并触发演变自愈。**验证路径只有一条（账本），失败有账可查、可纠正，不会"训崩丢状态"**。

---

## 4. 演变：场演化引擎

### 4.1 势函数与算子

- **势函数 V**：来自执行环境的 verdict（编译通过/测试绿/类型检查过）——**零人工标注**，即 verifiable reward（对应 2025-2026 的 RLVR）。
- **演化算子**：在守恒约束（ΔC=0）下对场做结构形变。类比既有 **涡环包（vortexRing）** 的拓扑变换——把"能力/策略"当作可在场上重组的拓扑结构，而非写死的 if-else。
- **驱动**：既有 `evolution` 闭环 + `GoalRunner` 续跑，复用 Agent 主循环，零新增运行时依赖。

### 4.2 这顺手统一了自改进 + A2A

- **自改进**：场在势函数 V 下形变，信用高的结构被保留、低的被淘汰 → 即 RLVR 轨迹优化（对应 RAGEN/StarPO），但**不需要再写一个"RL 模块"**，它是场的固有动力学。
- **A2A 互操作**：两个 OmniHarness 实例 = 两个**同构的场**。对接 = 让两场以同一 `ResAddr` 空间共振（复用 `cosmicWeb` 发现机制）。**不需要 Google A2A 的 Agent Card / HTTP/SSE 协议栈**——因为大家本就是同一种场，对接是几何同构而非协议翻译 → 无协议烟囱、无翻译后遗症。
- **身份**：`agentIdentity`（Ed25519）作为节点的 `addr` 签名分量，场间共振时天然验签，无需额外的信任层。

## 5. 三缺口如何"涌现"而非"焊接"（对照表）

| 调研缺口          | 焊接式做法（有后遗症）    | UCE 涌现式（无后遗症） | 为何无后遗症                  |
| ----------------- | ------------------------- | ---------------------- | ----------------------------- |
| 图上下文 repo-map | BM25 上焊 AST+PageRank 层 | 场的 `edges` 内禀拓扑  | 同一直射表示，无叠加边界      |
| 专属 eval 管线    | 另起 SWE-bench 跑分栈     | 守恒账本即 eval        | 一条验证路径，失败可回溯      |
| A2A 互操作        | 接 A2A/MCP 协议栈         | 同构场共振             | 无协议翻译，几何同构          |
| 自改进            | 写 RL 训练模块            | 场动力学（势函数驱动） | 复用 evolution 闭环，零新依赖 |
| 记忆              | 外挂向量库                | `kind=memory` 节点     | 与上下文同源，无同步边界      |

**核心论证**：焊接的后遗症来自"N 个模块 = N 套状态 + N-1 个同步边界 + N 条验证路径"；UCE 是"1 个场 + 1 条守恒 + 1 个演变"，一致性由构造保证，没有边界可漏。

## 6. 落地路线（学以致用：复用已有积木升格，不重写）

| 阶段 | 动作（升格而非新建）                                                            | 复用现有                    | 风险                            |
| ---- | ------------------------------------------------------------------------------- | --------------------------- | ------------------------------- |
| U1   | 立场：`resonantMemory` + `cosmicWeb` 合并为 **ResonantField**（统一 Node 表示） | 已有两原语                  | 低                              |
| U2   | 守恒账本：审计哈希链升格为 C 账本，加 `qecGrade` 综合征检测                     | AuditSink + qec             | 低                              |
| U3   | 场视图：上下文窗口/记忆/工具/Subagent 改为场的局部投影                          | contextAssembler + subagent | 中（重构切面）                  |
| U4   | 演变：势函数接 execution verdict，evolution 闭环驱动形变                        | evolution + GoalRunner      | 中（RL 不稳，需 StarPO 稳定化） |
| U5   | 同构对接：两场经 `cosmicWeb` + `agentIdentity` 共振                             | 已有两原语                  | 中                              |
| U6   | 统一 eval：账本闭合+零综合征 = 通过，接 CI 门禁                                 | evals/ + benchmark/         | 中                              |

> 顺序逻辑：U1–U3 把"表示"归一（消除多套状态）；U2 立守恒（消除账算不清）；U4–U6 让演变与互操作从场中长出。每一步都复用既有代码，**升格语义而非推倒重写**——这是"学以致用"，不是空谈。

## 7. 诚实声明（不诓骗）

1. **隐喻都有计算落地**：共振地址=结构哈希+拓扑编码；守恒=哈希链账本+能量增量校验；演变=势函数下的结构形变；涡环=拓扑变换算子；场=统一 Node 图。文档已逐条给算法形态，非玄学。
2. **"开创者 / 从没人做"的边界**：新颖性在「用**一条守恒律**统一 上下文/记忆/工具/智能体/eval/互操作」，把六件别人分模块做的事收进一个第一性框架。底层原子（哈希、图、哈希链、RLVR、Ed25519）都是已知技术；**新在范式层级，不在原子层级**——这点必须诚实。
3. **落地前是理论**：所有 KPI（token↓、Pass@k、eval 成本↓、A2A 延迟、演变曲线）须在 U1–U6 落地后跑真实数字填数；在拿到数字前，任何"领先"都是预言。
4. **RL 不稳定是已知坑**：RAGEN 明载 "Echo Trap"，U4 必须上 StarPO-S（轨迹过滤+批评者+梯度稳定），否则会训崩——已写入风险。
5. **OS 沙箱真机验证**仍是既有尾账（S78）；跨机场共振的真实隔离须等该尾账收口。

## 8. 成功度量（与框架同源，可测）

- **归一度**：系统状态是否收敛到单一 Node 图（无平行表示）= 架构一致性审计通过。
- **守恒度**：账本闭合率 100%；任意轨迹零未入账能量流。
- **演变增益**：势函数下场形变 N 轮后 mini-SWE-bench Pass@1 相对基线↑。
- **互操作零协议**：OmniHarness↔OmniHarness 对接不引入新传输/协议栈，仅靠同构场共振。
- **零标注**：势函数 100% 来自执行环境 verdict。
- **无后遗症**：架构审计确认"单场 + 单账 + 单演变"，无 N-1 同步边界。

### 收束

别人在做"功能堆叠"，我们在做"第一性还原"——把六件散装能力收进**一个场、一条守恒、一个演变**。这不是焊接，是**归一**；这不是修补，是**演变**；这不是追新，是**守恒**地长出新东西。落地前是设计，落地后跑出的数字，才是它是否配叫"开创"的唯一判据。
