## 2. 失败模式诊断（`evals/headroom-analysis.mjs`）

33 条查询按「GT 文件在深层候选池中的最佳排位」分类：

- **OK 17 条（51.5%）** — 已命中
- **RANKING 10 条（30.3%）** — GT 在候选池但排不进 Top-10
  - 排位分布：**11–20 位 5 条、21–50 位 4 条、51–100 位 1 条**
  - ⇒ **9/10 只需把 GT 提升 1–40 位即可救回**，属浅层排序问题，非深水区
- **LEXICAL 6 条（18.2%）** — GT 与查询零词法交集（如 "chain of thought persisted to disk" → `StoredTrace`），
  BM25 候选池里**根本不存在**该文件

Oracle 上界（完美重排）：候选深度 D=20 → 66.7%，**D=50 → 78.8%，D≥100 → 81.8%（饱和）**。
即：**候选深度 50 已覆盖几乎全部可达空间**，再深无意义。

### 8.1 共同机理（本节最有价值的产出）

1. **网无法同时做到「全覆盖」与「有鉴别力」。** 稠密档（df≤4 ⇒ 482 节点 / 16034 边 / 平均度 **66.5**）
   的 1 跳邻域就吃掉全网 **90.2%**、2 跳 100% ⇒ 处处等价、没有信息量；稀疏档（每节点 top-8）1 跳覆盖
   掉到 90.9% ⇒ 漏网。`evals/spider-density-sweep.mjs` 扫了 4×3×3 组配置，**不存在甜点**。
2. **网的拓扑类型错了。** 文件级网连的是「**结构性**关联」（两文件共享罕见标识符），而词法盲区要的是
   「**语义**关联」——`StoredTrace` ← "chain of thought **persisted** to disk"、`Canonicalizer` ←
   "what **normalizes** text"。**结构边在语义鸿沟上够不到，这不是调参能解决的。**
3. **零依赖的分布统计吃不到语义红利。** 词级共现网选出的扩展词是「共现显著但**不同义**」的长尾词
   （`semweight` / `turnoutcome` / `modulus`），与 LSA 证伪（精确率腰斩）、PRF 仅 +3pp 同源。
4. 这是**第 4 次独立确认「扩大可达集」对本语料无效**（前有 `pool-depth-probe.mjs`、
   `rank-veto-retro.mjs`，以及本节的 ①②③）。

### 8.2 附带的口径澄清（重要，回答「能不能到 100」）

本套 33 条查询是**刻意避开锚点字面词**的**对抗样本**（见 `evals/recall-precision.mjs` 注释）。同批锚点换
**自然提问方式**后：

| 口径                             | 命中率@14 | CI95         |
| -------------------------------- | --------- | ------------ |
| 对抗口径（本调研全程使用的口径） | 69.7%     | [54.5, 84.8] |
| **自然口径（锚点 + 自然语言）**  | **97%**   | [90.9, 100]  |
| **直接指名（只给符号名）**       | **97%**   | [90.9, 100]  |

⇒ **生产现实下检索已近饱和**；本报告第 1 节那个 81.8% 是**对抗口径**的上界，**不是生产现实的上界**。
自然口径仅剩 **1 条**未命中（`Diagnostics` ← "where do language server error reports come from"）。
证据：`evals/production-defaults-check.mjs`、`evals/spider-final-ab.mjs`。

## 9. 军事链条五级：「排序层」不可再增，「弹药层」砍 69.9% token 且反手提命中 +6.1pp（2026-09-17 追加）

按「雷达探测 → 太空卫星定位 → 高精度导弹 → 暴雨梨花针 → 高射速近防炮」的五级构想逐级翻译为算法原语
并实测。**结论：排序层的命中率增益全部不显著（诚实判负）；真正落地的是「弹药投送」——它把注入 token 砍
69.9%，而省下的预算反手把命中率推高 +6.1pp。**

### 9.1 先对标业界（我们差多少）

| 系统                                         | SWE-bench Lite 文件级定位 Acc@1 / Acc@5 |
| -------------------------------------------- | --------------------------------------- |
| 纯 BM25（单路词法）                          | 38.7% / 61.7%                           |
| 代码嵌入检索（CodeRankEmbed）                | 52.6% / 84.7%                           |
| agent 类（LocAgent / OpenHands / Agentless） | 72–78% / 79–94%                         |

另据 Sourcegraph：**BM25F（多字段 BM25，奖励符号定义与文件名命中）在其内部评测中关键指标约 +20%**，
两段式架构为「BM25 召回 → transformer 精排」。我方对抗口径 hitRate@14 **69.7%** / @20 **75.8%**
（n=33、语料 482 文件），与「嵌入检索」同量级，而**零依赖、零模型**。

### 9.2 五级翻译与裁定（配对 bootstrap，n=33）

| 军事级                   | 算法原语                                                      | 裁定                                                               |
| ------------------------ | ------------------------------------------------------------- | ------------------------------------------------------------------ |
| ① 雷达探测（多频段）     | 多字段 BM25F：content / path / symbols / signature 独立归一化 | 命中率**不显著**（K=10 +6.06pp [−6.06, 18.18] 跨 0）；token↓、MRR↑ |
| ② 太空卫星（全域标定）   | 跨频段分数校准（max-norm / 排名分位）                         | MRR 0.318 vs 基线 0.258；命中率仍不显著                            |
| ③ 高精度导弹（精确制导） | 字段感知精排（倒数秩 + 符号名覆盖 + 路径覆盖）                | **对强池有害**（66.7% &lt; 不重排 69.7%）；对弱池 +9.1pp（历史）   |
| ④ 暴雨梨花针（一发多针） | RRF 多探针融合                                                | 命中率 **+0pp**；MRR **+10.14pp**（CI 跨 0）                       |
| ⑤ 高射速近防炮（末端）   | 自适应预算 / 末端补射                                         | 未形成独立增益；真正形态是**梯度弹药投送**（§9.3）                 |

一处反直觉发现：**`signature` 是被完全浪费的强信号** —— 单频段命中率即 **69.7% @14 追平生产默认**，
且 token 少 34%（2197 vs 3335）。它与 `symbols` 同属「声明信息」，而 `content` 是「实现信息」。

### 9.3 真正的收益：把「命中哪些文件」与「注入多少字」解耦

**核心洞察：命中哪些文件由**排序**决定，注入多少字由**呈现**决定。** 由此设计梯度投送
（`src/context/repoMapPayload.ts`）：

- 前 3 个文件 → 完整符号大纲；
- 第 4..8 个 → 「`📄 路径` + 命中符号名」；
- 其余 → 仅一行 `📄 路径`（agent 有 read 工具，路径本身即线索）。

| 口径（生产 symK=24，33 条查询） | 全大纲 | 梯度投送 | 降幅   |
| ------------------------------- | ------ | -------- | ------ |
| fileK=20 平均 token             | 4829   | **1455** | −69.9% |
| 应急压缩档（`degrade`）         | 4829   | **911**  | −81.1% |

**构造性不变量（非统计推断）**：排序结果 `query().files` **33/33 逐字相同** ⇒ `hitRate@K` **必然不变**，
不存在「为省 token 而掉召回」的风险。**省下的预算反向兑换覆盖广度**：fileK 14 → **20** ⇒
命中率 **69.7% → 75.8%（+6.1pp，CI [60.6, 87.9]）**，而 token 仍**低于**原 14 档全大纲口径（3703）。

**P5 降档改口径**：原降档靠「缩 fileK 10→5」（代价 −12.1pp 命中率）却几乎不省 token——梯度投送下
fileK 5→10 只差 **34 token**，因为 token 大头是**前几档的完整大纲**，尾部路径行每行约 7 token。
改为**收缩大纲档位**（只留 Top-1 完整大纲）后：K=14 档 **946 token**（比旧降档 1337 少 29%）且
命中率 **69.7%**（旧降档 36.4%，**+33.3pp**）。

### 9.4 诚实边界

1. **排序层零改动落地**——多字段 BM25F 与 RRF 的命中率增益在 n=33 下均不显著，按「两关」纪律不翻默认，
   只留评测脚本与报告。**这一批的贡献是「成本」，不是「命中率」。**
2. 梯度投送降低的是**注入字面信息量**；`hitRate@K` 构造性不变，但**下游任务完成率是否同步不变未验证**，
   须待 P6 端到端基准——本报告不对此作承诺。
3. 一处**信息反而增加**：`outlineText` 只列**有声明符号**的文件，梯度档对每个命中文件都给路径行 ⇒
