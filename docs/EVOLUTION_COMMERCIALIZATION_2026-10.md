## 0. 结论摘要（TL;DR）

1. **可商业化的资产不是"自进化"这个神话，而是"可审计的自我改进治理层"。**
   2026 年市场的真实空位：研究侧的自进化（Sakana DGM / AlphaEvolve）**没有治理**；
   企业侧的治理（审计 / 沙箱 / 回滚）**没有自我改进**。本仓是少数两头兼备的基座：
   fail-closed 执行链 + 审计哈希链 + 双回滚（会话+代码）打底，进化闭环的六环骨架已在
   `src/evolution/` 建成且有单测，但三个生产化关键件处于断开/休眠（§2.2）。
2. **自进化不直接卖钱，它是溢价层与续约机制。** 没有客户为"agent 会自己变强"付钱，
   客户为"变强的过程可解释、可审批、可回滚、可入账"付钱。因此商业主张必须挂在**治理**上卖：
   **"唯一自带可审计自我改进的 agent 基座"**——每次能力晋升都有门禁裁决 + 哈希链证据 + 一键回滚。
3. **商业模式推荐：open-core 三条收入线。** 核心（harness）保持 Apache-2.0 换分发；
   ① **进化治理包**（企业版：License/RBAC/多租户/晋升治理台/合规导出增强）；
   ② **控制面**（托管或私有化的团队版：配额/审计中台/技能包分发）；
   ③ **进化资产市场**（签名技能包 + 安全分级 + 分成，远期）。
4. **落地前提是工程活，不是叙事。** 阶段 0「插电」五项（§5 阶段 0）：失败信号上产线、
   进化增益自证探针、CRISPR/固化器生产者接线、verifyCommand 自动推导 + 沙箱内进化、
   晋升级回滚。每项带**可证伪判据**，全部离线可判——沿用本仓纪律：**没有判据的提案不进路线图**。
5. **最重要的战略对冲：进化增益可能永远做不显著。** 研究侧最乐观的结果也只是特定任务域的
   局部提升；本仓自证纪律（两关统计）大概率判死多数"增益"。因此商业模式**押注治理而非增益**：
   增益是期权，治理是地基。增益做出来是超预期，做不出来商业模型依然成立。
6. **明确不做**（沿反泡沫清单续期）：递归自我改进（RSI）叙事、GPU RL 训练、向量库、
   无外部反馈的自我精炼循环、把 verifier 当完成判据、恢复重型跑分 CI。

## 1. 问题定义：本报告说的"自进化"是什么

**工程定义**（与本仓 `src/evolution/` 对齐）——一个六环闭环：

```
信号采集 → 提案生成 → 评估（可验证奖励）→ 晋升准入（fail-closed 门禁）→ 应用落盘 → 回滚兜底
```

进化对象按成熟度排序：技能（instructions/组合）→ 提示与规则片段 → 工具参数/暴露策略 →
代码级自修改（**本仓明确不做**，见 §8 反泡沫）。

**商业定义**——客户付费的对象不是闭环本身，而是闭环的三个副产品：

| 副产品             | 客户语言                           | 对应本仓资产                                                                                       |
| ------------------ | ---------------------------------- | -------------------------------------------------------------------------------------------------- |
| **随使用增值**     | "用得越久越懂我们团队/仓库"        | 技能沉淀 + 记忆生命周期 + 进化晋升（`src/skill/`、`src/evolution/`）                               |
| **变化的可审计性** | "它改了什么？谁批准的？证据在哪？" | 审计哈希链 + fail-closed 晋升门禁（`src/enterprise/`、`src/evolution/failClosedEvolutionGate.ts`） |
| **变化的可逆性**   | "不满意能一键回去"                 | checkpoint/rewind 双回滚（`src/core/checkpointManager.ts`）                                        |

**战略含义**：把自进化包装成能力叙事（"比别的 agent 更聪明"）是与模型厂正面作战——必败；
包装成治理叙事（"唯一敢在企业环境里开自我改进的基座"）是打信任缺口——正好落在 §3.3
实测的采纳鸿沟上（79% 试点 / 11% 规模化的差值就是钱）。

### 2.2 自进化子系统：六环逐环体检（胚胎期，骨架真、产线断）

| 环节     | 状态           | 证据                                                                                                                                                   |
| -------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 信号采集 | **断**（孤儿） | `src/evolution/failurePatternMiner.ts` 仅被自身与单测引用，无任何生产调用方；现役"发现"只做技能两两组合（`twistDiscoveryEngine.ts`），不做任务失败归因 |
| 提案生成 | 部分可用       | 组合式提案在跑；模型生成变体走 `rlvrLoop.ts`（StarPO 式 sample-filter-replay）                                                                         |
| 评估     | 可用但默认关   | `verifiableReward.ts`（RLVR：真跑用户 `verifyCommand` 取退出码）；未配 `--rlvr-verify` 时奖励恒 0、全旁路                                              |
| 晋升准入 | 可用           | `failClosedEvolutionGate.ts` + `promotionAdmission.ts`（多样性闸+退火）+ `rewardCoverageMeter.ts`（覆盖率 fail-closed 闸）                             |
| 应用     | 已接线         | `src/composition/runtime.ts` L58–93：`onPromote` 真落技能注册表 + `evolution.promoted` 观测行；主循环挂点 `src/core/agent.ts` L355/L564                |
| 回滚     | **缺进化级**   | 现有回滚是会话/代码级；技能晋升后无快照还原演练                                                                                                        |
| 外部证据 | **空白**       | 对外跑分子系统 2026-10-03 已删除；进化增益**从未被量化**（README 自述）；46 引擎默认真正干活的只有 2 个                                                |

**两个休眠执行体**：`src/adapters/skill/crisprSkillEditor.ts`（CRISPR 式技能编辑：语义寻址+定点
patch+差异测试+回滚）与 `src/adapters/skill/capabilityCrystallizer.ts`（能力结晶化）——机制完整、
带测试，但生产代码里**没有任何 `queue()` 调用方**（只有测试在调）。机器造好了，没人喂料、默认不插电。

**结论**：自进化子系统当前状态 = **L1（结构同构）**：闭环在、单测锁、但信号源、执行体、
默认开关三个生产化关键件断开。这与本仓成熟度语言完全一致——商业叙事绝不允许超出 L1。

### 3.3 信任鸿沟（本方案的需求侧依据）

- "**79% 企业已试点 agent，只有约 11% 规模化**"——差值的主因是信任与治理，不是能力
  （[AccuKnox](https://accuknox.com)、行业综述）；三大扩展障碍：集成复杂度、安全/治理风险、
  数据接入（[Natoma](https://natoma.ai)）。
- Gartner 2026 安全趋势：agentic AI 构成新攻击面（[Resilience Forward](https://resilienceforward.com)）。
- 实务建议高度收敛：**带审计轨迹的沙箱 + KPI 挂钩的高杠杆场景 + 可追溯可合规**先于放量
  （[Orange Business](https://perspective.orange-business.com)、[Berkeley CMR](https://cmr.berkeley.edu)）。
  —— 这份"实务清单"与本仓现有资产几乎逐条对位。

### 3.5 关键判断（从调研推出的三条）

1. **自进化是溢价层，不是获客层。** 获客靠"可靠执行 + 免费 + 模型中立"（harness 本体）；
   付溢价的是"我的 agent 在变强，且全过程我能审计"。对应：核心免费、进化治理收费。
2. **市场在给"资产层"独立定价。** Mem0 的 $350M 估值不是记忆算法的钱，是"跨应用的私有
   资产+迁移成本"的钱。本仓的同位资产 = 技能库 + 晋升史 + 失败签名库（**客户的私有数据，
   归客户**——这句话本身就是企业版卖点）。
3. **信任缺口 > 能力竞赛。** 把 §3.3 的实务清单逐条变成产品能力（审计中台、沙箱默认档、
   晋升审批流、合规导出），等于把行业采购标准写成了自己的路线图——且大半已经建好。

## 5. 产品化路线图（"完美实现" = 每项以可证伪判据收口）

> **完美的操作性定义**（拒绝"可用就行"）：
> ① 技术完美 = 六环全部有生产调用方 + 增益两关显著（或如实判死）+ 回滚演练常态化；
> ② 商业完美 = 每档价格有单位经济验算、每个功能有付费假设与验证里程碑；
> ③ 治理完美 = 企业三件套（SSO/RBAC/审计）+ 合规导出可通过客户法务审。
> 沿用本仓判据哲学：字面量断言、仪器自证、变异测试；**跑不出数字不得声称完成**。
> 与 [ARCHITECTURE_UPGRADE_2026-10.md](ARCHITECTURE_UPGRADE_2026-10.md) §4 的关系：E 系列全部站在
> 已落地的 G 系列守卫之上（G1 行为/检索守卫、G3 完成判定 fail-closed 是 E 系列判据的前提，已 ✅）。

### 阶段 1「单机商业版」（月 1–6）

- **F1 License 引擎**：机器指纹 + Ed25519 签名验证（复用 `src/adapters/identity` 与 CLI `identity` 能力）；
  判据：篡改 license ⇒ 拒（红）；过期 ⇒ 降级为核心功能而非停摆（诚实降级档）。
- **F2 进化治理台**（Web 工作台新 tab，复用 11 tab 框架）：晋升史/审计链可视化/一键回滚入口；
  判据：治理台展示的每条晋升记录都能用 `audit verify` 独立复核通过（数据与证据同源）。
- **F3 企业包初版**：RBAC-lite（角色 × 工具/审批策略绑定）；判据：越权工具调用被拒且 reason 可读（沿 G5 判据风格）。
- **F4 定价实验**：Pro 档发布（进化本地开启 + 治理台）；验证假设"治理台周活 ≥ 40% 的 Pro 付费用户"。

### 阶段 2「团队控制面」（月 6–18）

- G1 多租户 + 计费（席位 + 用量混合，锚定 §3.4 混合制趋势）。
- G2 技能包团队分发：`bundle pack/unpack`（已有 .ohb + HMAC）升级为带签名的私有技能源；
  判据：无签名包在严格档被拒（红）。
- G3 托管控制面（可选云或客户 VPC）：审计中台、配额（`quotaService` 已有底子）。
- G4 转化漏斗上线：Star→CLI 采纳（7 日 ≥N 次会话）→Pro→Team；北极星：**周活治理操作数**（审批/回滚/晋升查看）。

### 阶段 3「进化资产市场」（月 18+，装机量前置）

- H1 签名技能包市场：对齐 §3.4 市场趋势（技能目录 + 安全分级）；
  分级判据复用本仓门禁哲学：静态权限扫描 + 沙箱运行 + 差异测试，产出 A/B/C 评级——**评级即门禁输出，不是人工标签**。
- H2 分成与结算（70/30 起步）；H3 进化产物出证：技能包附带"进化系谱"（由哪个失败签名演化而来、
  门禁裁决记录）——市场里没人能提供这个，因为没人在晋升环节留哈希链。

### 阶段 0–3 共同的"不做"清单（反泡沫续期）

RSI/递归自我改进叙事；GPU RL 训练；向量库；无外部反馈的自我精炼（§3.9 已证掉分）；
verifier 当完成判据；重型跑分 CI 复活；并行写入型子代理。（逐条理由见
[ARCHITECTURE_UPGRADE_2026-10.md](ARCHITECTURE_UPGRADE_2026-10.md) §5。）

## 6. 定价与 GTM

### 6.1 定价结构（初版假设——每个数字都是待验证假设，不是结论）

| 档位         | 内容                                                    | 定价锚                                                                             |
| ------------ | ------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| Core（开源） | harness 全功能；进化闭环**代码在但默认关**，无治理台    | $0（Apache-2.0）                                                                   |
| Pro（个人）  | 进化开启向导 + 治理台 + 增益月报 + 签名技能包制作       | $15–29/月（对标主流 CLI agent 入门档区间，弱来源 [usekyros](https://usekyros.ai)） |
| Team         | 多席位 + 技能库共享 + 审计中台 + 私有技能源             | $25–50/席/月                                                                       |
| Enterprise   | 私有化 + SSO/RBAC/多租户 + 合规导出增强 + SLA + License | 五位数/年起                                                                        |
| 市场抽成     | 技能包销售分成                                          | 30%（远期，装机量前置）                                                            |

单位经济底线（商业化"完美"的判据之一）：毛利率 ≥ 80%（托管成本可算）；LTV/CAC ≥ 3；
Pro→Team 升级率作为治理台价值的直接读数。

### 6.2 GTM 双轨

**国际开源轨**：GitHub 分发 → 开发者自下而上 → open-core 转化。动作：README/landing 聚焦
"auditable self-improvement"差异点；发布 `evolutionLiftProbe` 报告作为技术博客（**负结果也发**——
本仓诚实文化本身就是最强的可信度营销，市场里没有第二家敢发）。

**国内私有化轨**：数据不出域 + 零运行时依赖 + 审计链（对齐等保/内审叙事）+ DeepSeek 等
OpenAI 兼容端点默认可用 → 目标客户：金融/政务/央国企的 agent 试点部门（正是 §3.3 的 11% 人群）；
渠道：信创集成商/行业 ISV（对应 §4.1 买家 D，以 OEM 授权承接，不建交付团队）。

### 6.3 冷启动第一批付费客户画像

1. 有硬审计需求的私有化试点团队（合规驱动，预算存在，容忍早期粗糙）；
2. 高流动团队的知识沉淀痛点（技能库=组织记忆，进化史=交接文档）；
   ——两者都**不**需要进化增益先被证明，只需要治理先被信任。这再次印证 §0 的战略对冲。

## 7. 护城河与可防御性

| 层                 | 内容                                                                                 | 强度评估                  |
| ------------------ | ------------------------------------------------------------------------------------ | ------------------------- |
| 审计数据与迁移成本 | 晋升史/技能库/失败签名是客户私有数据，沉淀即锁定（正向锁定：归客户，不搞数据绑架）   | ★★★★☆                     |
| 治理合规壁垒       | 哈希链审计 + fail-closed 门禁是**架构级**能力，补建成本≈重写执行链                   | ★★★★☆                     |

| 零依赖工程纪律     | 准入制依赖 + 分层隔离 → 私有化/信创适配成本最低                                      | ★★★☆☆                     |
| 双边网络（远期）   | 技能市场：买方要"带门禁证据的技能"，卖方要分发——评级门禁即平台壁垒                   | ★★★☆☆                     |

**最大威胁与应对**：模型厂附属 agent（Claude Code $2.5B ARR 量级）向企业私有化下探。
应对：不打 UX、不打模型，打**模型中立 + 治理深度 + 自托管**三件 Claude Code 商业上不卖的东西；
并让"治理化自进化"成为品类定义——若它将来跟进，说明品类成立，届时 open-core 的装机量与数据沉淀是谈判筹码。

## 9. 度量体系（进化质量 KPI × 商业 KPI）

**进化质量**（全部来自已有观测面，不新造仪器）：
晋升接受率；晋升后 7 天存活率（=1−回滚率，**核心**：晋升了但很快被回滚 = 假进化）；
两关显著增益的任务域占比；信号→提案→晋升的漏斗转化率；`evolution.promoted` 观测行覆盖率。

**商业**：激活（7 日内 ≥3 次真实会话）；进化开启率（账户维度）；治理台周活/付费用户；
Pro→Team 转化率；NRR（技能库沉淀度是 NRR 的先行指标）；企业 PoC→付费转化周期。

**客户价值读数（进化悖论指标）**：客户不关心闭环转了几圈，关心"这个月省了多少工时/
少踩多少坑"——治理台的月报必须翻译成任务完成率 × 人工替代工时，而不是晋升次数。
