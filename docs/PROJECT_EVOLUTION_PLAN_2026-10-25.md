# OmniHarness 能力升级总规划（2026-10-25）

> 目标：把 OmniHarness 做成**独立可构建、能力完整、长任务可靠、桌面/Web 体验一致**的
> 本地 Agent 工作台，而不是任何外部 harness 的“影子”或演示壳。
> 本文件是跨轮次的**总规划**；逐项实测与完成记录仍以 `docs/PROJECT_BOARD.md` 为准。

## 0. 当前基线

- 后端：TypeScript + 事件溯源 + JSONL/session 存档 + 工具门禁 + MCP + 多模型适配；测试 2700+。
- 前端：React 19 + Vite 单页工作台；流式、虚拟滚动、Markdown、文件面板、设置/插件/编排等。
- 桌面：Electron 44 外壳（main/preload + 内置 harness 侧车）；已有配置系统、中英 i18n、
  托盘、单实例、深链、自动更新骨架、崩溃自动重启。
- 性能：F1/F2/F3/F4/F5/F6/F7/F8/F9 主要热路径已落地；`perf:gate` 六项预算。
- 独立性：产品代码/配置/测试已无外部 harness 引用（`audit:independence`）。

## 2. 工作流 B：桌面端从“外壳”到完整应用

**现状**：配置/i18n/托盘/诊断/深链/崩溃重启已具备；仍是单窗口 + 内置侧车，设置/更新/日志/
任务进度等能力偏薄。

**Wave D1（体验）**

- 桌面设置面板：模型、工作区、语言、更新、日志、代理（复用 Web 设置协议，不复制业务）。
- 托盘：诊断（已做）、重启、工作区最近列表、暂停通知。
- 窗口：记住多显示器、最小化到托盘、任务栏进度、单实例深链聚焦。
- 原生菜单：最近工作区、打开日志、切换语言（即时生效）。

**Wave D2（交付）**

- 更新签名/校验/回滚；`electron-updater` 通道与 release 流程。
- NSIS 安装包体积/启动实测；安装/卸载/升级路径。
- 崩溃自动重启策略（已做）+ 崩溃转储上传（可选、默认关）。

**Wave D3（能力）**

- 本地文件拖拽、系统通知动作、剪贴板、全局快捷键。
- 离线模式/模型缓存管理、代理配置。
- 多窗口/任务面板（后续）。

## 3. 工作流 C：长任务成本、准确度与缺陷

**已完成**：F3 指纹缓存、F6 增量摘要、F8 增量 BM25、F9 breakdown 缓存、

**剩余**

1. **长任务基准**：固定 3 类任务（代码修改/多文件重构/长会话问答），记录 pass^k、
   token、时延、压缩次数；每次性能/提示改动回跑。
2. **F1 收尾**：写入路径级增量重建已做；补「新增/删除文件」的增量而非全量（可选）。
3. **S7 收尾**：审计组批/轮转/流式 verify，需先确认合规口径（丢事件窗口）。
4. **W1 稳定段**：流式 Markdown 只重渲染稳定块；需浏览器 Profiler 与 e2e 文本契约。
5. **S2 真机**：大会话首屏/加载更早的浏览器实测。
6. **失败模式**：工具循环、空转、重复读、压缩后失忆、审批卡死，逐项加检测/回归。

## 4. 工作流 D：多 Skill 并发与冲突

**问题**：多 skill 同时命中会重复注入、互相覆盖指令、增加 token；并发启动时争抢工具/
工作区/模型配额。

**方案**

1. **Skill 冲突检测**：按声明的 `tools`/文件 glob/资源域求交集；冲突即拒绝并发或串行化，
   并在 UI 显示冲突原因。
2. **去重与预算**：相同指令片段去重；每回合 skill token 预算 + 超限摘要；记录各 skill 的
   token/工具调用贡献。
3. **并发闸**：全局/工作区/资源三级信号量；skill 声明 `exclusive` 资源（如浏览器、测试端口）。
4. **可观测**：`skill.activated` / `skill.conflict` / `skill.budget` 事件与面板。
5. **回归**：多 skill 同时命中的 golden 任务，验证不重复注入、不互相覆盖、token 下降。

## 5. 工作流 E：Web 与桌面统一能力

- **共享协议**：Web/桌面共用 RPC/事件/设置 schema；桌面只加原生能力适配层。
- **能力矩阵**：文件系统、通知、托盘、深链、更新、快捷键、离线、模型缓存逐项标注
  Web/桌面支持度，缺口进 backlog。
- **统一 i18n**：原生壳与 Web 词条分治但同一语言偏好；桌面 `app.language` 可覆盖。
- **统一性能预算**：`perf:gate` 覆盖后端热路径，前端 bundle/流式另设预算。
