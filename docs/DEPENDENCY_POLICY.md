# 依赖准入政策（Dependency Admission Policy）

> 生效日：2026-09-05 ｜ 决策人：项目所有者 ｜ 取代旧铁律「零运行时依赖」
>
> 机器可读清单：[`dependency-allowlist.json`](../dependency-allowlist.json)
> 强制门禁：`scripts/check.mjs`（**阻断级**）· CI：`.github/workflows/ci.yml`

## 1. 政策正文

> **必要即可依赖。凡能实质提升项目能力、且经准入评审的优质依赖，即为本项目的资产。**
> 依赖不是债务，盲目拒绝依赖才是——自研一个劣化版的轮子同样消耗维护成本、同样不可靠。
> 但依赖也绝不是免费午餐：每一个进来的包都要**说得清收益、守得住边界、退得出去**。

### 1.1 与旧铁律的关系（不是全盘否定）

旧铁律「零运行时依赖」在其历史阶段是正确的：它逼出了零依赖 BM25、零依赖 RFC6455、零依赖 Ed25519 身份、手写 N-API FFI 等**真本事**，这些能力**全部保留、继续维护**，不因政策放宽而废弃。

新政策只在**一处**放宽：**当自研的边际成本显著高于引入、且引入能带来质变能力时，允许引入**。所有既有零依赖实现默认不动。

### 1.2 三条不可妥协的底线

1. **分层隔离**：第三方依赖**只能**出现在 `src/adapters/**`、`src/tools/**`、`src/cli/**`、`src/tui/**`、`src/util/**`、`src/search/**`、`src/context/**`。
   **`src/ports/**` 与 `src/core/**` 恒为第三方-free**——端口与核心只认接口，第三方永远进不来。
   这条保证：依赖可换、架构不塌。
2. **准入登记**：任何 `dependencies` 条目、任何第三方裸导入，**必须**先登记进 `dependency-allowlist.json` 并写明理由。未登记 = 阻断（exit 1）。
3. **许可证洁净**：仅允许 permissive 许可证（见 §2.4）。传染性 / 商用限制许可证一律拒绝。

## 2. 准入标准（六项，全部须满足）

### 2.1 能力增益（Gate: `reason` + `capability`）

必须写明**它带来什么原本没有的能力**，以及**为什么自研不划算**。
不接受「大家都用」「写起来方便」这类理由。

### 2.2 体积预算（Gate: `maxInstallKb`，报告级实测）

单个包的 install 体积默认上限 **2 MB**；超出需显式说明理由并单独审批。
理由：本项目目标含「消耗更低、使用条件更低」，包体膨胀直接伤害冷启动与分发。

### 2.3 依赖树收敛（Gate: `maxTransitiveDeps`，报告级实测）

传递依赖默认上限 **20 个顶层传递依赖**。依赖地狱比自研更贵。

### 2.4 许可证（Gate: `license`，**阻断级**）

允许（permissive）：
`MIT` · `Apache-2.0` · `BSD-2-Clause` · `BSD-3-Clause` · `ISC` · `0BSD` · `Unlicense` · `CC0-1.0` · `BlueOak-1.0.0`

拒绝（传染性 / 商用限制 / 来源不明）：
`GPL-2.0` · `GPL-3.0` · `LGPL-*` · `AGPL-*` · `SSPL-*` · `BUSL-*` · `CC-BY-NC-*` · `UNLICENSED` · 未知

### 2.5 可替换性（架构约束）

依赖**必须**落在适配器内部，对外只暴露本项目自己的端口类型。
评审时回答一个问题：**若该包明天停更，换掉它需要改多少文件？** 答案必须是「1 个适配器文件」。

### 2.6 维护度（人工评审）

- 近 12 个月内有发布，或 issue 区活跃；
- 无已知未修复的高危 CVE；
- 优先选择 ESM 原生、无 postinstall 脚本、无原生编译（避免抬安装门槛）。

## 3. 准入流程

1. 提出议题：写明 §2.1–§2.6 六项内容；
2. 在 `dependency-allowlist.json` 的 `allowlist` 中登记条目（`reason` / `capability` / `license` / `approvedAt` / `layer` 为**必填**）；
3. `npm install <pkg> --save`（落入 `dependencies`，不是 devDependencies）；
4. 跑 `npm run check` —— 未登记、字段缺失、许可证非法、核心层导入，均**阻断**；
5. 提交时 PR 描述须附「能力增益」与「退出成本」两项说明。

## 4. 退出机制

登记条目里须写 `exitPlan`（一句话：若该包废弃，替换路径是什么）。
无法写出合理退出路径的依赖 = 不允许引入。

## 5. 门禁行为（`scripts/check.mjs`）

| 规则名               | 级别             | 检查内容                                                        |
| -------------------- | ---------------- | --------------------------------------------------------------- |
| 依赖准入清单         | **阻断**         | `dependencies` 每项须在 allowlist 登记                          |
| 依赖登记字段完整     | **阻断**         | `reason`/`capability`/`license`/`approvedAt`/`layer` 缺一即阻断 |
| 依赖许可证合规       | **阻断**         | 许可证须在 permissive 集合内                                    |
| 第三方导入须准入     | **阻断**         | `src/**` 的第三方裸导入须在 allowlist 内                        |
| 核心与端口层零第三方 | **阻断**         | `src/ports/**`、`src/core/**` 禁止第三方导入                    |
| 依赖体积预算         | 报告（可实测时） | 单包 install 体积 > `maxInstallKb` 告警                         |
| 传递依赖收敛         | 报告（可实测时） | 传递依赖数 > `maxTransitiveDeps` 告警                           |
| 未使用的已装依赖     | 报告             | allowlist 已登记但 `src/**` 无导入 → 提示清理                   |

> 报告级项在 `--strict` 下升级为阻断。
