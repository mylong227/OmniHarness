# OTel 导出评估（Wave A.5 第三项 · B 级「先测后买」）

- 日期：2026-10-04
- 对象：`@opentelemetry/sdk-trace-base` + `@opentelemetry/otlp-transformer`（替代自研 `src/observability/otlpTraceExporter.ts`，217 行）
- 依据：[ARCHITECTURE_TARGET_2026-10.md](ARCHITECTURE_TARGET_2026-10.md) §5.3（判据①对账一致 / ②golden 哈希不变 / ③体积实测在预算内）、[DEPENDENCY_POLICY.md](DEPENDENCY_POLICY.md) §2 六门

## 结论：**维持自研（不引入）**

不是「因为零依赖」——那是 D10 §1.3 明令禁止的拒绝理由。三条实测理由如下。

## 一、判据③（体积）——**实测超预算 8.9 倍**

在**临时前缀**安装（`npm install --prefix <temp> --no-save`，不动本仓 `package.json`/lock）后实测：

| 指标             | 实测                                       | 政策预算                     | 判定        |
| ---------------- | ------------------------------------------ | ---------------------------- | ----------- |
| 请求的包         | 2（`sdk-trace-base` + `otlp-transformer`） | —                            | —           |
| **实际拉入的包** | **10**                                     | ≤ 20（`maxTransitiveDeps`）  | ✅          |
| **安装体积**     | **18,234 KB ≈ 17.8 MB**                    | ≤ 2,048 KB（`maxInstallKb`） | ❌ **8.9×** |
| 许可证           | 全部 Apache-2.0                            | 仅 permissive                | ✅          |

体积构成（前四）：`semantic-conventions` 11.7 MB、`sdk-metrics` 1.8 MB、`otlp-transformer` 1.0 MB、`api` 978 KB。
注意 `sdk-metrics` / `api-logs` / `sdk-logs` 是**被牵连**进来的——本仓只发 trace，用不到它们。

> 体积超预算本身不必然否决（ONNX 嵌入模型就是带 `budgetOverrideReason` 引入的先例），**但**按政策它要求
> 「自研边际成本显著高于引入、能带来质变能力」——见下一条：本次实测**没有**这种质变。

## 二、判据①②——评估开始时**根本不存在**，本轮把它们造出来了（这是本次评估最大的产出）

评估第一步就发现：`ARCHITECTURE_TARGET` §5.3 判据②写的是「既有 golden 哈希不变（过渡键并行策略保留）」，
但仓内**没有**这道判据——原测试只断言「POST 发生过 / 失败被丢弃」。线格式改一位、过渡键删一个，
**不会有任何判据变红**。同理判据①「`observabilityReconcile.mjs` 对账一致」断言的是**归因恒等式**，
它吃事件、与导出器无关：换不换 SDK 它都不会变，属**必要不充分**。

故本轮先补两道判据（迁移验收面），再据此评估：

| 判据                   | 落点                                    | 锁住什么                                                                           | 变异自证                                            |
| ---------------------- | --------------------------------------- | ---------------------------------------------------------------------------------- | --------------------------------------------------- |
| **线格式 golden 哈希** | `tests/unit/otlpWireGolden.test.ts`     | OTLP 报文体逐字节指纹（`sha256 = 8d37ea36…`），跨两次运行实测稳定                  | 改任意一位 ⇒ 红                                     |
| **过渡键并行**         | 同上                                    | 模型 span 上新键与旧键**按字面量**并存（`session.id`/`model.name`/`tokens.*`）     | 删任一旧键 ⇒ 红（用常量枚举断言则恒绿，故用字面量） |
| **数值形态**           | 同上                                    | token 计数必须走 `intValue`（int64 的 proto3 JSON 是字符串）                       | 改 `stringValue` ⇒ 红                               |
| **线 ↔ 账目对账**      | `tests/unit/otlpTokenReconcile.test.ts` | 线上 token 之和 == `TokenAttribution` 账目总数；缓存读是 prompt 子集、**不得相加** | 让导出器把缓存读加进输入 ⇒ 红                       |

> 写这两道判据时踩了两次坑，都记在文件注释里：① 判据夹具把 `exp` 塞进「声明覆盖」被 `setExpirationTime` 覆盖，
> 「已过期」用例其实什么都没验；② 拿**单个**模型 span 去对**整份**账目（模型 span 是按次记账的，账目是会话级），
> 100 !== 110 —— **错的是判据不是实现**。两次都是「判据自己没立住」，正是 §11.3 要防的形态。

**基线结论**：当前自研导出器在上述四面上**全绿**。也就是说——

## 三、能力增益评估——**不显著**

| 面               | 自研现状（实测）                                                                       | SDK 会带来什么                                      | 对本仓是否构成正确性风险下降                                                       |
| ---------------- | -------------------------------------------------------------------------------------- | --------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 线格式正确性     | 已被 golden 哈希 + 过渡键 + `intValue` 判据锁死                                        | 同（SDK 也依赖 `otlp-transformer` 生成同样的 JSON） | **否**——风险面已被判据覆盖                                                         |
| token 与账目一致 | 已被对账判据锁死                                                                       | 同                                                  | **否**                                                                             |
| 发送失败         | 静默丢弃 **+ 自观测计数**（`spansDropped`/`lastDropReason`，`http_<状态码>` 也算丢弃） | 重试队列 + 指数退避                                 | 是增量能力，但本仓当前口径是「可观测性不得反噬业务，丢弃必须可见」——**丢弃已可见** |
| 协议形态         | OTLP/**JSON** over HTTP，`AbortSignal.timeout(5000)`，批量 64                          | 另含 protobuf/gRPC、gzip                            | 当前需求面之外                                                                     |
| 覆盖面           | 只发 trace                                                                             | metrics / logs / propagators / sampling             | 当前需求面之外                                                                     |

**结论**：切换的收益（正确性风险下降）**实测不显著**，而代价是 17.8 MB / 10 个包（8.9× 预算）。
按 §5.3「若实测显示切换收益不显著则维持自研」，判**维持自研**。

## 四、复评触发条件（写清楚，免得下次又从零讨论）

满足任一条件时**重新评估**（届时本轮的 golden 哈希与对账判据就是迁移的**验收基线**）：

1. 需要导出 **metrics 或 logs**（当前只发 trace）；
2. 需要**重试/退避**语义（当前是「丢弃 + 计数」，若某天要求「不丢」则守卫队列是自研要重写的那部分）；
3. 需要 **OTLP/gRPC（protobuf）** 或 gzip；
4. 需要 **sampling / propagators / baggage** 等跨进程上下文传播能力。

## 五、本轮的诚实边界

- **未做**：没有真的把生产路径切到 SDK 上跑一遍端到端（那需要先引入依赖，属「买了再测」——
  与 B 级「先测后买」相反）。故判据①②的结论口径是「**当前资产在这两面上绿**」，
  而不是「SDK 在这两面上也绿」；后者要等复评时做。
- **未改**：`dependency-allowlist.json` **未新增条目**（未引入），`package.json` 未变动。
- 临时安装目录仅用于实测，已在使用后清理，不进仓库。
