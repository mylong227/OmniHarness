# OmniHarness Web 工作台 —— 设计系统

> 本文是 **Web 前端视觉的唯一事实源**。改样式前先读这里；改完 token 必须回填本文的对照表
> （漂移时以 `web/test/a11yContrast.test.ts` 与 `web/test/colorSystem.test.ts` 门禁为准，
> 门禁红了就是漂移了）。
>
> ## 2026-10-18 · 「纸与墨」重设计（Redesign · Replace）
>
> 上一版是**零色相**的纯黑/纯白单色体系。它的纪律成立（层级只靠明度），但真实长时间使用
> 下来有两件事不舒服，用户的原话是「极简设计，色彩构图需要舒适」：
>
> 1. **底色太极端**：纯 `#000` 的暗色与纯 `#fff` 的亮色都在"顶眼睛"，亮色下正文对比
>    19.8:1 远超阅读所需。
> 2. **没有色彩构图**：全站只有明度时，当前项、主行动、错误、成功都只能靠字形去猜。
>
> 本轮换掉整个视觉世界（保留全部 class 契约、DOM 结构与交互）：
>
> - **底**：中性色带极轻的冷调——暗色是石墨 `#17191c`，亮色是纸白 `#f8f7f4`，正文对比落在
>   15–16:1（清晰但不发光）。
> - **一个签名色**：靛墨（dark `#a8b4e8` / light `#3d4a86`），只承担四种语义：
>   主行动、当前/选中、链接、焦点。全站没有第二个品牌色。
> - **语义色恢复色相，全部低饱和**：成功=鼠尾草绿、失败=茜红、告警=琥珀、信息=雾蓝。
>   它们只出现在"需要被区分"的小面积上（徽标、diff、状态点、告警条），从不铺满表面。
> - **层级仍只有三件事**：表面阶梯、发丝线、留白。投影只留给真浮起来的浮层。
> - **对话是主角**：助手消息**不再套卡片**，直接躺在纸面上（上一版是卡片里套卡片、
>   再套代码块，三层边框把一屏切成十几个格子）。
>
> 实现归属（**加载顺序 = 优先级**，完整清单以 `web/src/main.ts` 的 import 顺序为准，
> `a11yContrast` 门禁按它解析级联序，孤儿文件会红）：
>
> | 文件                                                    | 职责                                                               |
> | ------------------------------------------------------- | ------------------------------------------------------------------ |
> | `web/styles/theme.css`                                  | **唯一配色事实源**：全部颜色 token、圆角/动效、reset、原生控件兜底 |
> | `web/styles/tokens.css`                                 | 只放 theme 之外仍被引用的 token（当前仅 `--font-sans`）            |
> | `web/styles/layout.css` · `components.css` · `chat.css` | 结构层：骨架 / 组件 / 对话流（几何与行为）                         |
> | `web/styles/shell.css`                                  | 壳层：三栏（会话侧栏 / 对话 / 右侧面板）                           |
> | `web/styles/base.css`                                   | 全局底子（排版 / 滚动条 / 选区 / 焦点环）+ 并入的旧打磨层 A 段     |
> | `web/styles/overlays.css` · `resilience.css`            | 浮层 / 错误边界与无障碍                                            |
> | `web/styles/shell.css`                                  | 壳层：三栏（会话侧栏 / 对话 / 右侧面板）+ 并入的旧打磨层 B 段      |
> | `web/styles/minimal.css`                                | **「纸与墨」设计体系（本轮重写）：唯一视觉事实源**                 |
> | `web/styles/highlight.css`                              | 语法高亮（**必须最后加载**，用来盖住 vendor 主题）                 |
>
> 每一层仍是「回滚成本 = `main.ts` 删一行」。**新增视觉调整优先写进 `minimal.css`**
> （它是设计事实源），结构层（layout/components/chat/shell）只放几何与行为。
>
> 右栏顶栏（`.rv-tabs`）在 `layout.css` 里是 `position: sticky; top: 0`，因此**必须不透明**：
> 现在写的是 `background: inherit`（随 `.col.right` 底色，深浅主题一致）。背景一旦写回
> `transparent`，整列滚动时正文会从标签底下透出来（2026-10-19 用户截图复现过）。

## 1. Design Read（这份 UI 是什么）

| 维度                | 取值                                                                      |
| ------------------- | ------------------------------------------------------------------------- |
| artifact            | 开发者工作台（对话为主轴 + 遥测/治理侧栏），非营销页、非仪表盘            |
| audience            | 本机开发者，长时间盯屏、键盘优先、10cm–1m 视距                            |
| visual-language     | **纸与墨**：暖中性底 + 单一靛墨签名色 + 低饱和语义色（Linear / Arc 一系） |
| mode                | Redesign · Replace（保留全部 class 契约与交互，换掉整个视觉世界）         |
| visual-variance     | 3（明度 + 一个签名色 + 四个低饱和语义色族）                               |
| motion-intensity    | 2（140–220ms 的颜色/透明度位移，无入场大动画）                            |
| information-density | 8（事件流可能上千条，一屏信息量是刚需）                                   |
| asset-dependence    | 1（无品牌素材依赖：自研图标集 + 字符标识）                                |
| brand-fidelity      | 5（无外部品牌规范，自建并在此固化）                                       |

**定位四问（每个表面都要能回答）**

- **叙事角色**：对话流是主角（hero）；左右栏与顶栏是配角（chrome），必须退到背景里。
- **观看距离**：1m 笔记本 → 正文 14.5px / 行高 1.7、侧栏 12.5–13px；不做投影阅读尺度。
- **视觉温度**：安静、精确、**微冷**——底色是冷石墨/纸白，墨是偏紫的靛。
  温度差是刻意的：暖底冷墨让"当前/主行动"不需要靠加粗就能看见。
- **容量 check**：单屏（1280×900）须同时容纳左栏 248 + 中栏对话 + 右栏 360；
  中栏正文最大行宽 800px（超过就该换行，不是拉宽）。

**反 AI 陈词（本项目的硬约束，违反即回退）**

1. 不用紫→粉→蓝渐变、不堆 emoji 当图标、不用「圆角卡片 + 彩色左边框」。
2. 不编造数据、不加装饰性分区；每个元素都要能回答"删掉它是否变差"。
3. 图标只用自研线性 SVG 集（`web/src/ui/models/Icon.ts`），不再新增 emoji 图标。
4. **颜色只做信号**：一块彩色表面会立刻变成"分类"而不是"状态"。
   语义色只出现在 ≤40px 高的徽标/行内标记/状态点上，不铺满卡片。

## 2. 色彩

### 2.1 策略：Restrained（克制）

中性底承担 >95% 的面积，签名色只做四件事，语义色只在需要区分时出现。
这是"操作型界面"该有的色彩预算——不是"不敢用色"，而是**颜色的每一次出现都必须有职责**。

### 2.2 表面阶梯（surface ladder）

| 层            | dark      | light     | 用途                             |
| ------------- | --------- | --------- | -------------------------------- |
| `--bg`        | `#17191c` | `#f8f7f4` | 中栏对话底、应用底色             |
| `--bg-elev`   | `#121417` | `#f1f0ec` | 左/右栏底、浮层、模态            |
| `--panel`     | `#1e2126` | `#fdfcf9` | 卡片、输入区、气泡、面板         |
| `--panel-2`   | `#282c32` | `#e9e8e3` | 卡中卡、hover 底、下拉触发器     |
| `--panel-sel` | `#343a43` | `#dde2e7` | 菜单里"当前项"的选中底           |
| `--code-bg`   | `#101215` | `#f4f4f2` | 机器产物底（代码块、diff、JSON） |

> 两套主题的"前进方向"一致：**更亮 = 更靠前**（亮色下卡片比纸底更白，暗色下卡片比底更亮）。
> 这是刻意统一的语义，组件因此不需要写 `[data-theme]` 分支。
> 相邻表面的明度差只有 1.04–1.09:1：能读出来，但不构成色块。

### 2.3 描边三档（职责固定，不要混用）

| token             | dark      | light     | 观感（对 panel） | 用在哪                                             |
| ----------------- | --------- | --------- | ---------------- | -------------------------------------------------- |
| `--hairline`      | `#262b31` | `#e4e4e0` | 1.19–1.23:1      | 栏内分隔、列表行、区块之间——「呼吸」，不画格子     |
| `--border-soft`   | `#353b43` | `#d5d6d1` | 1.42–1.43:1      | 容器边缘：卡片、输入卡、代码块、浮层（**默认档**） |
| `--border`        | `#6b7480` | `#7d838c` | 3.41–3.72:1      | **控件边界**：表单、按钮、徽标（WCAG 1.4.11）      |
| `--border-strong` | `#8b95a3` | `#5d646d` | 5.32–5.83:1      | hover / 聚焦的增量提示                             |

> 3:1 的义务只对「控件边界」成立（用户要能看出这里可以点/可以输入），
> 对「容器边缘」不成立——容器的层级由表面阶梯表达，不需要靠描边画格子。
> 这是上一版用两轮真机反馈换来的结论，别再合并这三档。

### 2.4 文本

| token     | dark      | light     | 对 `--bg` | 对 `--panel-2` | 用途                 |
| --------- | --------- | --------- | --------- | -------------- | -------------------- |
| `--text`  | `#eceef2` | `#1a1d21` | 15.2–15.8 | 12.1–13.8      | 正文、标题           |
| `--dim`   | `#aab2bd` | `#565d66` | 8.2–6.2   | 6.6–5.4        | 次要信息、元数据     |
| `--faint` | `#8d96a2` | `#5f666f` | 5.9–5.4   | 4.7–4.7        | 装饰、禁用态、微标签 |

正文不再拉到 21:1：那是纯白配纯黑才有的读数，长时间阅读会"发光"。

### 2.5 签名色（靛墨）

| 角色         | 用法                                           | token                   |
| ------------ | ---------------------------------------------- | ----------------------- |
| 作**底色**   | 主按钮、发送键、分段控件当前项、徽标实心       | `--accent` + `--ink-fg` |
| 作**字色**   | 链接、当前项文字、选中图标、焦点环             | `--accent`              |
| 作**淡底**   | 当前会话 / 当前菜单项 / 当前分栏（8–13% 墨色） | `--accent-soft`         |
| 作**细线**   | 输入卡聚焦描边、按钮 hover 边                  | `--accent-line`         |
| 按下 / hover | 实心墨块的加深档                               | `--accent-2`            |

dark：`--accent: #a8b4e8` / `--ink-fg: #14161c`（8.7:1）；light：`--accent: #3d4a86` /
`--ink-fg: #fdfcf9`（8.1:1）。两套主题语义一致，所以 `--accent` 可以放心地同时出现在
"底"和"字"两个位置。

> **铁律**：一屏之内实心墨块 ≤ 2 处（当前项 + 主行动）。靛墨是页面上唯一的"高音"，
> 用滥了互相抵消——这正是彩色体系里「品牌色面积 <5%」的同一条纪律。

### 2.6 语义色：低饱和，只做信号

| 语义   | token    | dark      | light     | 对 bg（dark/light） | 表达方式（除颜色之外）         |
| ------ | -------- | --------- | --------- | ------------------- | ------------------------------ |
| 成功   | `--ok`   | `#8fbf9f` | `#3a7150` | 8.5 / 5.4           | 状态点 + `✓` 字形 + 文案       |
| 失败   | `--err`  | `#e89a92` | `#a6362f` | 7.9 / 6.1           | 淡色圆角底 + `✕` + 文案        |
| 告警   | `--warn` | `#d4b06a` | `#7d5a1c` | 8.6 / 5.9           | **虚线描边**（唯一的虚线语义） |
| 信息   | `--info` | `#9fb3d9` | `#3f5680` | 8.3 / 6.9           | 来源/重命名徽标                |
| 新增行 | `--add`  | `#8fbf9f` | `#3a7150` | 8.5 / 5.4           | 12% 底 + 行首 `+`              |
| 删除行 | `--del`  | `#e89a92` | `#a6362f` | 7.9 / 6.1           | 12% 底 + 行首 `-`              |

用法纪律：

- 徽标 = `color-mix(in srgb, var(--x) 10–12%, transparent)` 底 + 同色字 + 同色 40% 描边。
  面积小到不构成色块，只做"扫读时的形状"。
- **不加**彩色左边框（>1px 的彩色竖条是上一代的 AI 味来源）；diff 行也只用 12% 同色底 +
  行首 `+/-`，不再画 2px 左缘（2026-10-20 用户：「类似的竖线全去掉」）。
- **文本块的分区一律用淡色圆角底**：引用块（accent 8%）、过程步骤区（panel 42%）、
  错误条（err 8%）、toast（语义色 8%）。竖线只保留在**栏与栏的结构分隔**上，不参与文本排版。
- 状态点（8px 圆点）可以用纯语义色：它是信息密度最高、面积最小的表达。

### 2.7 为什么是"一个墨 + 四个淡色"

工作台的信息密度极高（事件流 + 遥测 + 治理）。一旦界面上出现 8 种色相，颜色就同时冒充
「状态」与「分类」两种语义，信号被稀释成装饰。这一版给颜色划了职责：**靛墨 = 交互**，
**低饱和语义色 = 状态**，其余全部由明度承担。读一屏的时候只有一条规则：越亮越靠前，
带色的是"需要看一眼"的东西。

## 3. 字体

```css
--font-sans: system-ui, 'Segoe UI', -apple-system, 'PingFang SC', 'Microsoft YaHei', …;
--mono / --font-mono: 'JetBrains Mono', 'Cascadia Mono', ui-monospace, …, Consolas, monospace;
```

- **为什么保留系统栈**：本仓铁律是"离线可用、零网络依赖"，不许引 Google Fonts；
  `Inter`/`JetBrains Mono` 只在用户本机已装时命中（`local()` 语义），否则无缝回落。
- **中西文分工**：界面文案走 `--font-sans`；**一切机器产物走 `--mono`**——路径、工具名、ID、
  token 计数、diff、JSON、代码、时间戳、徽标。这条分工是"工具感"的主要来源，比配色更有效。
- **字阶**（`minimal.css §1` 的 `--fs-*`）：11 / 11.5 / 12.5 / 13（机器产物）/ 13.5（UI）/
  **14.5（正文）** / 16（面板标题）/ 22（指标数字）。不做营销页那种 4–6× 比例。
- **行高**：正文 1.7（中文舒适区），列表 1.35–1.45，机器产物 1.6–1.65。
- **等宽数字**：所有会跳动的数字（计时、token、金额）必须 `font-variant-numeric: tabular-nums`。
- **时长口径**：思考计时 / 工作状态条 / 回合结果卡统一走 `models/DurationFormat.ts`——
  超过 1 小时显示「小时/分钟/秒」三段，不把时长累加成「75分3秒」或纯秒数。
- **微标签**：`.col-head` / `.section-title` 等用 11px + `letter-spacing: 0.06–0.07em` +
  uppercase——小字号靠字距而非字重取得可读性。
- **行宽**：中栏 `.stream-inner` 最大 800px（约 72 个中西混排字符），超宽屏居中不拉伸。

## 4. 间距 · 圆角 · 阴影 · 动效

- **间距**：4px 基准栅格（`--sp-1..8` = 4/6/8/12/16/20/24/32）。口径是「**组内紧、组间松**」：
  `.ev` 之间 22px、过程簇内 2px、标题上方 > 下方。
- **圆角**：只允许 **6（微）/ 8（小件）/ 10（控件）/ 14（卡片）/ 18（大表面）/ 999（胶囊）**。
  半径随容器层级递增（控件 8–10 < 卡片 14 < 模态 18），层级才读得出来。
- **阴影**：**只用于"浮起"**（菜单、模态、命令面板、toast），两层：接触阴影 + 环境阴影。
  卡片/输入框/面板**从不**投影——"假深度"在长时间使用里最先变成噪音。
- **零装饰**：无渐变（`background-image: none`）、无 `backdrop-filter` 模糊、无内高光、无发光焦点环。
  焦点一律是 2px 靛墨实环（`outline`）+ 一层极淡外晕。
- **动效**：`--dur-1: 140ms`（颜色/描边）、`--dur-2: 220ms`（位移/展开）、
  `--ease: cubic-bezier(.2,.7,.3,1)`。**禁止**给 `.ev` 加入场动画（中栏是虚拟列表，
  重挂会重放动画 ⇒ 视觉上一直在闪）。全局尊重 `prefers-reduced-motion`。

## 5. 图标 · 代码 · 原生表面

**图标**：唯一来源 `web/src/ui/models/Icon.ts`（自研线性 SVG，24×24 视框、`currentColor`、
圆端圆角）。**铁律：不再新增 emoji 当图标**（字形随系统字体变、尺寸基线不受控、
**不跟随 `currentColor`**，hover/选中态无法与文字一起变色）。
图标恒为装饰性：根节点固定 `aria-hidden="true"`，可读名字由外层按钮的 `aria-label` 提供。
容器里一律要有 `flex: none`（flex 子项默认可收缩，19px 图标会被压成约 8px 宽的竖条）。

**代码高亮**：`highlight.css` 用**字重 + 字形 + 明度**表达层级，不用色相——
在一屏只有一处"机器表面"的设计里，彩色语法会变成第二个色彩系统，把注意力从对话拉走。
表格（关键字/字符串/数字/标点/注释）见该文件头注释。

**原生表面**（最便宜、也最容易被跳过的一档）：

- 选区 `::selection` = 26% 靛墨淡底（不是整段反白：阅读中选中一段代码时，反白会"闪"）。
- 插入符 `caret-color`、`accent-color`（复选框/单选）、`color-scheme`（滚动条/原生控件）、
  `scrollbar-color` 与 `::-webkit-scrollbar` 全部跟随 token；滚动条静止几乎隐形、悬停才显形。
- 焦点环 2px `--accent`；输入卡内的 textarea **不出**自己的环（焦点由容器表达）。

### 6.1 按钮语言（全站只有三档）

| 档位       | 外观                     | 用法                               |
| ---------- | ------------------------ | ---------------------------------- |
| primary    | 靛墨实心（`--accent`）   | **唯一主行动**（发送、确认、允许） |
| default    | 发丝轮廓（`--border`）   | 表单行、对话框次要动作             |
| ghost/text | 无框，hover 落 `--hover` | 次要动作、图标钮                   |

实心墨块在全页**最多 2 处**（当前项 + 主行动）；第 3 处开始互相抵消。

> **发送键几何（2026-10-20）**：40×32px、11px 圆角的扁圆角矩形（不再是 32px 圆点）；
> 停止键共用同一几何。用户反馈「太圆了，扁平一些、方一些，带点椭圆感」。
>
> **输入区双层结构（2026-10-20）**：外层 `.composer` 是 26px 发丝圆角框（四角全圆、**含顶边**；

### 6.4 命令面板（Ctrl/Cmd+P / K）

- **结构**：搜索头（镜片图标 + 无环输入 + Esc / 清除）→ 分组列表 → 页脚（结果计数 + 键帽）。
  键盘说明不再塞进 placeholder；placeholder 只回答「这里能搜什么」。
- **几何**：580px 宽、40px 内嵌搜索条（四周留 8–10px 呼吸位）、42px 行高、组标题上方 10px；窄窗 ≤560px 贴边并隐藏页脚键帽。

- **命令名**：面板组直接显示「工具 / 指标 / …」，不再逐行重复「打开面板：」前缀；
  分组名参与搜索，输入「面板」仍可收窄到整组。
- **手势**：↑↓ 移动、Enter 执行、Esc 关闭；选中项自动滚入视野。
- **滚动条例外**：`.cmdk-list` 是「菜单默认隐藏滚动条」的唯一例外——16 条命令必然越界，

- **判据**：`commandPalette.test.ts`（过滤 / 键盘 / ARIA）、`a11yContrast.test.ts`、

### 6.5 回合结果卡（`.turn-summary`）

- **职责**：一轮结束后只出现一次的结果面。过程簇负责「做了什么」，结果卡负责「留下了什么」。
  写类工具的产物卡不再散在过程流里；`turn_diff` 与工具回执按路径去重后统一进卡。
- **结构**：头部（`package` 图标 + 「本轮结果」+ 数量摘要 + 耗时 + 增删合计 + 收起）→
  「生成的文件」组 → 「修改的文件」组。每行 = 图标 + 目录（暗）+ 文件名（亮）+ 增删数 +
  差异 / 打开 / 下载。生成组按 `turn_diff` 的 hunk 旧侧行数是否为 0 判定；草图和其它
  diff 覆盖不到的产物按工具语义补位。
- **耗时**：取本轮首尾事件时间戳之差（`TurnSummary.durationMs`），显示为
  「耗时 2分18秒」；不足 1s 不显示。格式化统一走 `models/DurationFormat.ts`——
  思考计时、工作状态条、结果卡三处同一口径：**超过 1 小时显示「小时/分钟/秒」三段**，
  不再出现「75分3秒」或一直累加的纯秒数。
- **几何**：`panel` 表面 + 发丝边 + 10px 圆角；行高 34px，组标题 8px 上留白；窄窗（≤1024px）
  隐藏数量摘要、增删合计与「差异」文字按钮（保留「耗时 + 数字」），路径保留文件名（目录可截断），
  行点击仍可展开差异。
- **判据**：`turnSummary.test.ts`（纯模型：合并 / 去重 / 分组 / 耗时）、
  `durationFormat.test.ts`（时/分/秒换算）、`turnSummaryCard.test.ts`（真 Chrome：分组 /
  增删 / 耗时 / 展开差异 / 收起）。

### 6.6 品牌标识与动效（2026-10-20）

- **形状**：28×28px 的方形淡墨芯片（`border-radius: 10px / 6px`，四角呈**椭圆弧**而不是标准
  四分之一圆）；底色为 `color-mix(accent 15%, panel)`，Ω 字用签名色——用户「背景框太亮、太方正」
  与后续「太扁了、要方感、圆角椭圆一点」的反馈，靠降低底色面积与椭圆角解决。品牌识别度来自
  Ω 字形 + 独有芯片形状。
- **字标**：`Omni` 主标题 + `HARNESS` 小号大写副标（同一行后置、垂直居中，9px / 0.12em 字距，
  3% 文本色淡底；底色刻意做到“认真看才发现”）。扫光与 glow 只作用于 `Omni`，副标保持安静。
- **动效**：芯片 5.6s 慢呼吸（±1px / 1.5%），每 8.4s 一次扫光；`Omni` 上叠一层
  `aria-hidden` 的同文字，用 `background-clip:text` 让一道淡墨光带每 8s 扫过（基字保持实色，
  对比度与朗读都不受影响）。
- **工作状态条**：去掉外框与左侧高亮条，复用同一枚芯片的紧凑版（20×20，7/5 椭圆角，
  1.7s 呼吸 + 外晕），旁边是动作与耗时。品牌识别不靠高亮块，靠同一枚 Ω 芯片出现在
  「品牌头」与「干活中」两处。
- **降级**：`prefers-reduced-motion: reduce` 下关闭全部品牌动画与扫光。
- **判据**：`shellDensity.test.ts`（`Omni` 主字标 + `HARNESS` 副标 / 收起按钮可达）、
  `colorSystem.test.ts`（颜色来自 token）、`a11yContrast.test.ts`；视觉留档见
  `web/archive/session-*.png`。

### 6.7 思考流式面（`.ev.reasoning.live`）

- 去掉原来的**左侧竖线**（2026-10-20 用户反馈）；改为 `color-mix(panel 72%, transparent)` 的
  **很轻圆角底**（10px）+ 10px/14px 内边距，只负责把“这段是思考”与纸面轻轻分开。

### 6.8 上下文步骤行（`.tc-verb` / `.tc-subject` / `.tc-meta`）

- **不再显示工具名**。每行两列：左列固定宽度 4.6em 的**动作标签**（思考 / 读取 / 写入 / 编辑 /
  运行命令 / 浏览 / 搜索 / 委派 / 生成草图 / 更新待办 / 查看计划…），右列对象（路径 / 命令 / 查询 /

### 9.1 已知边界（诚实记录）

- 旧打磨层已**解散**（2026-10-18）：9 个 `polish-*`/`refine-*` 先按加载相位折叠为 `legacy-a/b`，

## 10. 无障碍：从「两条手工判据」到「真实引擎全量审计」（2026-10-18）

此前只有 `a11yContrast`（颜色 4.5:1）与 `a11yKeyboard`（焦点可见 / roving tabindex）两条手工判据。
它们看不见**结构性缺陷**：tablist 里混入非 tab 子项、交互控件嵌套、按钮可访问名与可见文本不一致。
本轮引入 **axe-core**（devDependency，MPL-2.0，仅测试期使用、不进入产物）跑 WCAG 2.1 A/AA 审计，
并修掉它检出的全部 serious/critical：

| 违规（axe id）                           | 根因                                                                                 | 处置                                                                                                       |
| ---------------------------------------- | ------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| `aria-required-children`（critical）     | 右栏 `role=tablist` 里同时放了「全部面板」按钮与收起按钮                             | tablist 只包标签（新 `.rv-tablist` 容器）；非 tab 控件移到 tablist 外                                      |
| `nested-interactive`（serious）          | 关闭「×」是 `role=button` 的 span，嵌在 `role=tab` 里                                | 「×」改为 `aria-hidden` 的指针捷径；键盘关闭 = 聚焦标签后 Delete/Backspace（`aria-keyshortcuts="Delete"`） |
| `label-content-name-mismatch`（serious） | `.new-chat`（aria-label「新建会话」vs 可见「新会话」）、`.mp`（fixlabel 不含模型名） | 可访问名改为**包含可见文本**（WCAG 2.5.3）                                                                 |
