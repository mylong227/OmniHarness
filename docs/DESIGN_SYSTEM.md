# OmniHarness Web 工作台 —— 设计系统

> 本文是 **Web 前端视觉的唯一事实源**。改样式前先读这里；改完 token 必须回填本文与
> `web/test/a11yContrast.test.mjs` 的对照表（两者漂移时以门禁为准，门禁红了就是漂移了）。
> 实现归属：`web/styles/theme.css`（token 定义）+ `web/styles/polish.css`（打磨层，最后加载）。

## 1. Design Read（这份 UI 是什么）

| 维度                | 取值                                                                 |
| ------------------- | -------------------------------------------------------------------- |
| artifact            | 开发者工作台（对话为主轴 + 遥测/治理侧栏），非营销页、非仪表盘仪表盘 |
| audience            | 本机开发者，长时间盯屏、键盘优先、10cm–1m 视距                       |
| visual-language     | 工具型人文／hairline 高地平线（Linear / Vercel / Raycast 一系）      |
| mode                | Redesign · Preserve（保留全部 class 契约与交互，换视觉层）           |
| visual-variance     | 4（克制：靠比例、留白与描边建立秩序，不靠花色）                      |
| motion-intensity    | 3（微交互只有 120–200ms 的位移/透明度，无入场大动画）                |
| information-density | 8（事件流可能上千条，一屏信息量是刚需）                              |
| asset-dependence    | 1（无品牌素材依赖：自研图标集 + 字符标识）                           |
| brand-fidelity      | 5（无外部品牌规范，自建并在此固化）                                  |

**定位四问（每个表面都要能回答）**

- **叙事角色**：对话流是主角（hero）；左右栏与顶栏是配角（chrome），必须退到背景里。
- **观看距离**：1m 笔记本 → 正文 13.5px、行高 1.6、侧栏 12–13px；不做投影阅读尺度。
- **视觉温度**：安静、精确、略带金属感的冷灰（权威但不冰冷），拒绝"科技霓虹"。
- **容量check**：单屏（1280×900）须同时容纳左栏 248 + 中栏对话 + 右栏 360；故侧栏信息用 12px
  与紧凑 4px 栅格，中栏正文 13.5px、最大行宽 880px（超过就该换行，不是拉宽）。

**反 AI 陈词（本项目的硬约束，违反即回退）**

1. 不用紫→粉→蓝渐变、不堆 emoji 当图标、不用"圆角卡片 + 彩色左边框"。
2. 不编造数据、不加装饰性分区；每个元素都要能回答"删掉它是否变差"。
3. 图标只用自研线性 SVG 集（`web/src/ui/models/Icon.ts`），不再新增 emoji 图标。
4. 单色为主 + **一个**品牌强调色；语义色（成功/失败/告警）只在状态位出现。

## 2. 色彩

### 2.1 分层（surface ladder）

四层表面 + 两条描边，层级靠"亮度差 + 发丝线"表达，不靠阴影堆叠：

| 层                | dark      | light     | 用途                             |
| ----------------- | --------- | --------- | -------------------------------- |
| `--bg`            | `#0b0c0e` | `#fbfbfc` | 应用底色（含极轻的顶部径向渐变） |
| `--bg-elev`       | `#101114` | `#ffffff` | 顶栏、粘性表头、抽屉、弹层       |
| `--panel`         | `#141518` | `#ffffff` | 卡片、输入区、列表容器           |
| `--panel-2`       | `#1a1c20` | `#f2f3f6` | 卡中卡、下拉触发器、hover 底     |
| `--border`        | `#26282e` | `#e4e5ea` | 发丝描边（1px，替代阴影）        |
| `--border-strong` | `#3a3d45` | `#d2d4db` | 强调描边：hover、选中、kbd       |

> **为什么 `--border-strong` 必须 ≥3:1**：UI 组件边界（开关、输入框、卡片的可见轮廓）按
> WCAG 1.4.11 属"非文本对比度"，与文本无关但同样要求 3:1。`#3a3d45` on `#141518` = 3.36:1。

### 2.2 文本

| token             | dark      | light     | 对比度（on `--bg` / `--panel`） |
| ----------------- | --------- | --------- | ------------------------------- |
| `--text`          | `#e9eaec` | `#16181d` | 15.8:1 / 14.0:1                 |
| `--dim`           | `#9a9fab` | `#5c6270` | 7.6:1 / 6.7:1                   |
| `--faint`（新增） | `#6b7280` | `#7b818f` | 4.3:1 / 3.8:1 —— **仅限装饰性** |

`--faint` 不达 AA，**只允许**用于不承载信息的图形（分隔点、空态插画底、禁用态里的装饰）。
任何文字一律 `--text` / `--dim`。

### 2.3 品牌与语义

| 语义           | token        | dark      | light     | 说明                                                               |
| -------------- | ------------ | --------- | --------- | ------------------------------------------------------------------ |
| 品牌强调       | `--brand`    | `#7aa2f7` | `#1d5fd0` | 焦点环、选中标记、链接、进度条                                     |
| 品牌底（实心） | `--brand-bg` | `#2b4a8f` | `#1d5fd0` | 实心按钮底；文字用 `--brand-on`                                    |
| 成功           | `--ok`       | `#4ec97a` | `#1a7f37` | 工具成功、已连接、通过                                             |
| 失败           | `--err`      | `#f0616d` | `#cf222e` | 错误、断开、危险操作                                               |
| 告警           | `--warn`     | `#e0b341` | `#9a6700` | 重连中、完全访问、待确认                                           |
| 新增行         | `--add`      | `#3fb950` | `#1a7f37` | diff `+`／文件新增                                                 |
| 删除行         | `--del`      | `#f85149` | `#cf222e` | diff `-`／文件删除                                                 |
| 中性信息       | `--info`     | `#8fb8ff` | `#1d5fd0` | 重命名、引用、来源徽标（**与品牌同色系**，浅色下取值同 `--brand`） |

**铁律**：`--brand` 只在"当前/可交互/焦点"三种语义上出现。一屏之内品牌色面积应 <5%，
多了就变成"另一种花色"，也就失去了"这个才是重点"的表达力。

### 2.4 为什么单一强调色而不是彩色面板

工作台的信息密度极高（事件流 + 遥测 + 治理）。多色会让"状态"与"分类"两种不同语义互相冒充；
单色 + 语义色把颜色这件事变成**状态专用信号**：看到颜色就知道"有事发生"，而不是"这块属于某类"。

## 3. 字体

```css
--sans: 'Inter var', 'Inter', system-ui, 'Segoe UI', 'PingFang SC', 'Microsoft YaHei', sans-serif;
--mono: 'JetBrains Mono', 'Cascadia Mono', ui-monospace, SFMono-Regular, Menlo, Consolas, monospace;
```

- **为什么保留系统栈**：本仓铁律是"离线可用、零网络依赖"，不许引 Google Fonts；`Inter`/`JetBrains Mono`
  只在用户本机已装时命中（`local()` 语义），否则无缝回落到系统栈，不会产生字体加载失败。
- **中西文分工**：界面文案走 `--sans`；**一切机器产物走 `--mono`**——路径、工具名、ID、token 计数、
  diff、JSON、代码。这条分工是"工具感"的主要来源，比配色更有效。
- **字阶**（UI 而非文档）：11 / 12 / 12.5 / 13 / 13.5（正文）/ 15（面板标题）/ 20（指标数字）。
  正文与 h1 比例不做营销页那种 4–6×：工作台要的是"稳定层级"，不是"海报冲击"。
- **等宽数字**：所有会跳动的数字（计时、token、金额）必须 `font-variant-numeric: tabular-nums`，
  否则每次跳动都会横向抖一下。

## 4. 间距 · 圆角 · 阴影 · 动效

- **间距**：4px 基准栅格（4/6/8/10/12/14/16/20/24）。组件内边距取 8–12，容器取 14–18。
- **圆角**：`--radius: 8px` 为控件基准；容器 12–14px；胶囊 999px。
  **不为每层都加大圆角**——半径随"容器层级"递增（控件 8 < 卡片 10 < 面板 14），层级才读得出来。
- **阴影**：只用于"浮起"（弹层、抽屉、toast），从不用于卡片。
  `--shadow-1` 轻（菜单）、`--shadow-2 = --shadow`（弹层/抽屉）。深色下阴影几乎不可见 ⇒ 深色里
  靠 `--border-strong` + 提亮底来表达浮起，这是深色 UI 的必修课。
- **动效**：`--dur-1: 120ms`（hover/颜色）、`--dur-2: 180ms`（位移/展开）、
  `--ease: cubic-bezier(.2,.7,.3,1)`。**禁止**给 `.ev` 加入场动画（中栏是虚拟列表，
  重挂会重放动画 ⇒ 视觉上一直在闪，见 `web/styles/chat.css` 的注释）。
  全局尊重 `prefers-reduced-motion`：动效时长归零，但**状态变化仍必须可见**（靠颜色而非位移）。

## 5. 图标

**唯一来源**：`web/src/ui/models/Icon.ts`（自研线性 SVG 集，24×24 视框、`currentColor` 描边、圆端圆角）。
**铁律：不再新增 emoji 当图标。** 理由：emoji 字形由系统字体决定（Windows / macOS 各不相同）、
尺寸与基线不受控（对齐全靠手调）、彩色字形破坏单色层级、且**不跟随 `currentColor`**
（hover / 选中态无法与文字一起变色）。语义符号（`✓ ✗ ↻ ▸ ▾ × →`）不属于图标，可以保留在文案里。

```ts
import { icon } from '../models/Icon.js';
icon('wrench', { size: 14 }); // → <svg aria-hidden="true" focusable="false">
```

- 图标**恒为装饰性**：根节点固定 `aria-hidden="true"`，可读名字一律由外层按钮的 `aria-label` 提供。
- 尺寸由调用方给（默认 16）；容器里一律要有 `flex: none`——flex 子项默认可收缩，图标会被压成竖条
  （本轮实测：19px 图标被压成约 8px 宽，看上去像几个空方块）。`polish.css` 已对全部图标容器统一加护栏。
- 模型层（如 `AddMenuModel`）**只存图标名**，由组件层映射到 `icon()`；这样模型保持零 React 依赖、
  可直接在 node 下单测，且拼错图标名是**编译期**错误。

### 6.1 面板可达性（硬契约）

**任何面板都必须有入口，且不得依赖 hash 路由或特定视口宽度。** 收敛前 `RightPanel` 的标签条与
`NavRail` 各写一份清单：变更 / 治理 / 文件 / 详情在标签条里有、在 rail 里没有，而标签条在桌面端
（≥881px）是 `display:none` ⇒ 桌面用户要看「变更」只能手改 hash 或把窗口压窄到 ≤880px。

现在的结构（判据：`web/test/mount.test.mjs` 的「面板注册表」用例）：

```
PANELS(12) ├─ rail: true  (9) → 导航竖条常驻按钮
           └─ rail: false (3) → 竖条底部「更多面板」菜单（渲染 PANELS 全集）
   且 rail 集合 ∩ 非 rail 集合 = ∅，两者之并 = PANELS
```

`rail: true` 的挑选口径 = **日常高频 + 需要常驻状态**；`rail: false` = **由上下文触发**
（变更来自工作区改动、治理是按需审计、文件来自点文件/产物）。"不常驻"不等于"够不着"。

### 6.2 空 / 加载 / 错误 三态

三者必须**一眼分得开**——原先它们都只是"一行灰字"，用户分不清"这里没数据"和"数据读挂了"：

| 形态          | 何时用                              | 实现                                                           | 观感                                |
| ------------- | ----------------------------------- | -------------------------------------------------------------- | ----------------------------------- |
| `.empty.illu` | 列表为空，**且需要指引下一步**      | `emptyState(icon(...), 主文案, 指引?)`                         | 图标槽 + 主文案 + 灰指引，48px 留白 |
| `.empty.note` | 过程提示（读取中…）/ 结论即全部信息 | `emptyNote(文案, { icon })`                                    | 一行灰字 + 小图标，16px 留白        |
| `.empty.err`  | **加载失败**                        | `emptyNote(文案, { kind: 'err' })` 或 `emptyState(..., 'err')` | 红色 + 警示图标                     |

错误态用 `emptyState` 时把 `kind` 放在第四参（第三参是指引，可传 `undefined`）。
判据：`format.test.mjs`（结构）+ `a11yContrast.test.mjs`（`.empty.err` 的红色必须达 AA）。
