# Web / 桌面能力矩阵（2026-10-25）

> 目的：把“Web 能做什么、桌面多做什么、两者共用什么协议”写成一张可验收的表，
> 避免桌面壳重复实现 Web 业务，也避免桌面能力散落成不可发现的隐藏功能。
> 状态：`✅` 已具备 ｜ `◐` 部分/只有壳 ｜ `✗` 缺口。

## 1. 共享层

| 能力             | Web | 桌面 | 说明                                 |
| ---------------- | --- | ---- | ------------------------------------ |
| RPC / 事件流     | ✅  | ✅   | 同一套 server 协议；桌面只换承载窗口 |
| 会话/事件/工具卡 | ✅  | ✅   | 同一 React Web UI                    |
| 设置 schema      | ✅  | ✅   | Web 设置为主；桌面附加 native 分区   |
| i18n             | ✅  | ✅   | Web 词条 + 原生壳 `app.language`     |
| 主题/布局        | ✅  | ✅   | 桌面窗口复用 Web 布局                |
| 深链             | ✗   | ✅   | `omniharness://open?workspace=`      |
| 单实例           | ✗   | ✅   | 第二实例聚焦已有窗口                 |
| 多窗口           | ✗   | ✅   | 视图/托盘「新建窗口」，共用 Harness  |

## 7. 验收口径

- 每个 ✅ 必须有判据（单测/集成/真机脚本）；

- 桌面新增能力优先做“Web 无替代”的原生项，不在壳里复制业务逻辑。
