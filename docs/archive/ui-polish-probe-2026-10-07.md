真机探针的价值就在这里——下面每一条**单测都看不见**，是"打开真 Chrome 看"才暴露的。

| #   | 症状（用户视角）                                 | 根因                                                                                                                                                               | 修法与判据                                                                                                                                                                         |
| --- | ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 左栏导航全是**空方块**，看不出是什么             | `svg` 作为 flex 子项默认可收缩，19px 图标被压成约 8px 宽的竖条                                                                                                     | `polish.css` 对全部图标容器加 `flex:none` 护栏；`visualProbe --measure` 实测宽高 = 19×19                                                                                           |

## 4. 同轮收口的既有红灯（另一条重构线的中间态）

进来时 `web:test` 是 **303 pass / 15 fail**，全部报
`Cannot read properties of undefined (reading 'attach'/'detach'/'view')`——「视图代数」重构的中间态。
本轮按用户确认的语义收口：

- **默认挂载**（`detached === false`）：全新控制器 / 刷新 / 深链都必须能收流式事件。
  早期版本把默认设成"已摘"⇒ 正常路径**静默丢事件**（界面"连上了却一个字不来"）。
- **只有点「新建」才摘**；`loadThread` 重新挂上。
- **每次挂 / 摘都开新的一代**：换视图有两条路（新建 / 切会话），两条都收敛到
  `epoch() !== 我记下的代数` 这一条判据。
- 归属：状态对象由 `SessionController` 持有（`sessions.viewAttachment`），**摘与挂同源**。
- 判据：`web/test/viewAttachment.test.mjs`（5 例：默认挂载 / 摘 / 重挂 / 换视图 / 代数只增不减）
  - `turnControl.test.mjs` 的「回合进行中点新建，收尾不得把旧会话拽回视图」回归用例。

同时把流式生命周期从控制器里抽成 `models/TurnStreamBuffer.ts`（原先"字段 + 惰性工厂 + 释放口"三个成员
散在控制器里，而控制器已在上帝类阈值上——本仓惯例是**抽出去**而不是放宽阈值）。
抽完 `SessionController` 回到阈值以内，**编码标准增量门禁转绿**。

## 5. 坑与纪律（值得记档）

- **增量门禁读的是"暂存版"**：`auditStandards.mjs --delta` 比较的是 index 里的内容。
  改了源码却没 `git add`，门禁看到的还是别人（或你自己）上一次暂存的旧版本 ——
  本轮就因此误判过一次"类缺 JSDoc"，实际工作区早已补好。**跑这条门禁前先 `git add`。**
- **PowerShell 的字符串替换会静默吞掉 JSX 尖括号**：本轮用它批量改 emoji 时，
  `'<div` 被写成 `sdiv`、`Record<string` 被写成 `Recordsstring`，一次写坏两个文件
  （靠 `git checkout` 复原 + 改用 Node 脚本 / 编辑工具才收场）。
  **在中文 + JSX 混排的文件上不要用 PowerShell 做代码改写。**
- **删面比加面值钱**：面板截图好看不代表交互态好看。命令面板、审批模态、三个浮层、
  目录选择器、流式中间态这 10 个交互态**全都不在静态截图里**，本轮把它们纳入探针后才看清层级与浮起是否成立。

**未通过（1 项）**：`L`「回合进行中点『+ 新建』，回合结束后视图仍为空」。
诚实交代清楚，不含糊：

- **不是**"我改坏了"这一类可以一句话结案的结论，也**不是**已验证的应用缺陷：
  同一判据**单独跑通过**、`--only=E,L`（含一条真回合前置）也通过，只有**整跑**才红。
- 我做过一轮带仪器（临时改已构建产物 + 临时改判据脚本，**均已还原**）的实测，拿到的硬事实：
  1. 事件流没被污染：`handleEvent` 的守卫**确实在丢弃**已摘视图的事件（`detachedDrop=3`）；
  2. 点「新建」后现场是干净的：`hash=#pane=tools`、无高亮会话、回合收尾时**没有**把旧 threadId 写回；
  3. 但收尾时存在 `.ev.assistant`（`流式卡=0`，即**落成的**助手事件而非残留的流式文本）；
  4. 判据前序（E→F 刷新→J→K）会把"上一条真回合"的余波带进来，且 `ComposerDraft` **有意保留**
     上一条提示词 ⇒ 新输入会被**追加**成一条更长的提示词（这会让回合长得完全不同）。
- 我没能在这轮里把"整跑下那颗助手事件的确切来源"钉死。**不猜、不掩盖**：
  它留在项目看板上作为待办，触发条件与已排除项都写在上面，下次可从 F 的刷新恢复那条线继续查。

**已做的加固（保留在脚本里，缩小这类假红的来源）**：判据开始时先等上一条的在飞回合收干净、
清空输入框再发、把"在飞"改成**请求级**信号（`turns.run` 的 pending 计数，30ms 粒度）——
原先用 400ms 轮询 DOM 标记，快模型下一次轮询就错过，判红可能来自"没赶上"而不是"应用拽回视图"。
