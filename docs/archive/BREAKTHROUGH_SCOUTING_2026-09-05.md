# 突破侦察报告：代码混合检索天花板（67%→≥80%）

_日期：2026-09-05 · 针对 `recall-codebase-real.mjs` 真实语料（src/）_
_现状诚实基线：minilm 59.2% / e5-large 64.8% · KPI「67%→≥80%」未达成_
_瓶颈本质：文档表示绑定——每文件只嵌 1 条「截断前 600 字符」语义向量 + 通用句向量喂代码，丢掉函数体深处语义；BM25 已覆盖全文，故单纯加 chunk 召回是噪声（已翻 `false`）。_

---

## 0. 先泼盆冷水（纪律回放）

上半场我们用 2×2 受控消融证明：`chunkRecall` 是噪声、`e5-base` 不翻、`e5-large` 是唯一真实容量杠杆（+5.6pp）但 17.5× 构建税自杀。结论：**瓶颈不在「分不分块」，在「怎么表示一份代码」**。本报告所有候选都必须回答同一个问题——它是否改变了「文档→向量」的表示方式，且能本地 ONNX 离线落地 + 带可证伪 2×2 消融。拍脑袋加旋钮的税我们已经交过双份了。

## 2. 跨学科理论映射（数/理/化/生 → 可借鉴机制）

> 不是炫学。每条都对应一个**可落到代码检索的具体动作**。

### 📐 数学

- **谱方法 / 图谱拉普拉斯（Chung《Spectral Graph Theory》）**：调用图 Laplacian 特征向量作检索先验（PageRank-on-callgraph）。→ 动作：给 BM25/RRF 叠加「被高频调用的符号」结构先验，作为第三路轻量信号。
- **Learning-to-Rank / LambdaMART（Burges 2010）**：已进 Tier-2 D。把融合从「拍权重」升级为「学权重」。
- **信息论（Shannon 率失真）**：我们已撞上「压缩 7.97× vs 召回」的率失真墙。→ 动作：把召回下降量化为「失真度」，对每次表示改动做率失真权衡，别为省 token 牺牲召回。
- **最优传输（Wasserstein, Villani）**：换模型（e5→C2LLM）时，用 OT 对齐两嵌入空间分布，避免全量重嵌。→ 排期靠后，先验证 A 是否值得换。

### ⚛️ 物理

- **重整化群 RG（Wilson / Kadanoff）**：粗粒化代码结构是 RG 思想——repo-map 已是 RG 式粗粒。→ **关键动作：多尺度表示**。文件→函数→块三级各自嵌入，RG 要求「粗粒度特征在缩放下不变」，这恰好论证「Late Chunking（B）在文件级保留函数级上下文」是对的表示层级。
- **相变 / 临界现象**：67% 天花板是「相变点」——同质性（加更多同范式向量）无法越过，必须换「序参量」（表示方式）。→ 直接支撑结论：别在 BM25+minilm 范式里加料，换 A/B/C。
- **扩散检索 / 能量模型 EBM（LeCun；DDPM Ho）**：把查询嵌入当「噪声初态」，扩散去噪推向相关文档区域。重，暂排期。
- **张量网络 MPS（Orús）**：长上下文序列表示的压缩理论，是 Late Chunking 的数学底。→ 佐证 B 的理论正当性。

### 🧪 化学

- **分子指纹 Morgan/ECFP（Rogers & Hahn 2010）**：把代码 AST 子树哈希成「结构指纹」，与 BM25 的 token 重叠（Jaccard/Tanimoto 相似）互补。→ **动作：AST 子树指纹作第四路轻量结构信号**，零 LLM、零重嵌。
- **相似性集成 SEA**：类比「多模型投票检索」，与 RRF 同源。

### 🧬 生物

- **免疫系统（克隆选择 Burnet / 阴性选择 Forrest 1994）**：我们的 `rlvrLoop` 回放缓冲本就是「免疫记忆」。→ **决定性动作：自适应难负例挖掘**——把 eval 中**失败查询当「病原体」**，优先用它们做模型选择/微调与 hard-negative 构造，而不是均匀采样。阴性选择 ↔ 我们已有的 fail-closed 拒无关文档。
- **突触修剪**：嵌入空间稀疏化（我们已做 7.97× 压缩）即「剪枝」； pruning 应保高召回连接、砍低信息连接。
- **进化/遗传算法（Holland）**：已进 `rlvrLoop` 进化闭环，与免疫记忆协同。

## 6. 实验 1 实测判读（2026-09-05 晚，已出全 2×2）

受控变量：模型（minilm / jina-base-code）× 表示（前600字符 / 全文8000字符），端到端 src/ 真实语料，33 查询，FILE_K=14。

| 单元格 | 模型           | 表示           | Hybrid 召回 | Δ vs BM25 43.3% |
| ------ | -------------- | -------------- | ----------- | --------------- |
| 基准   | minilm         | 600字符+符号名 | **59.2%**   | +15.9pp         |
| ①      | jina-base-code | 600字符        | 56.1%       | +12.8pp         |
| ②      | jina-base-code | 全文(8000字符) | **54.5%**   | +11.2pp         |

**判读（硬结论）：**

- **证伪「喂更多字符破天花板」**：全文版比 600 版低 1.6pp、比基准低 4.7pp。
- **证伪「换代码专用模型即破天花板」**：jina 在同 600 表示下比通用 minilm 还低 3.1pp。
- **真因**：天花板卡在「向量浓缩了什么信号」，非「喂了多少字」。600 版显式把**符号名**浓缩进向量（文件身份最强信号）才赢；全文版稀释了该浓缩信号 → 降。
- **真·Late Chunking（token 级池化保块信号）≠ 我实现的「全文截断单向量」**：后者已证伪；前者需 token 级嵌入（当前 `embed` 接口不暴露）+ jina 8K 装不下大文件，非快赢。
- **实验 1 结论：翻车。minilm+600+符号名 59.2% 仍王，KPI 67% 未破。**

**修正后的假设（实验 1b，进行中）：** 把文件文档从 `rel+符号名+600原始代码` 改为 `rel+符号名+签名`（**浓缩身份、去原始代码噪声**），预期可超 59.2%——直接检验「浓缩身份」最优假设。已加 `--doc-mode id` 开关，minilm 快速消融中。

**实验 3（reranker）修正：** 原计划 `bge-reranker-v2-m3` 在本地 transformers.js **不可行**（Xenova 无该权重、BAAI 版无 ONNX）。改用 **`Xenova/bge-reranker-large`（1024d，BAAI 旗舰，含代码多语言）**，镜像已确认有完整 ONNX，探针下载中。零重建、查询期精排、可回退——仍是破 RRF 语义稀释噪声（EscalationPort −8.3pp）的最高 ROI 杠杆。已新建 `src/ports/reranker.ts`（第三方-free 端口）。

**收敛顺序：** 等 ① 实验1b(minilm+id) 出数 → ② reranker 探针确认加载+打分 shape → ③ 实现并跑实验3(bge-reranker-large 精排 top-N→top-K) → 取「最优表示 × 最优融合」组合，端到端证 ≥67%（或诚实记录未达成）。

## 6. 实验 3 落地 + 重新发现「其他好方案」（2026-09-05 续）

### 6.1 jina 出局，minilm+id 锁定为王

- jina + 浓缩身份(id) = **52.9%**，比 minilm+id(62.3%) 还低 9.4pp。代码专用模型在「符号名浓缩文档」上反而更差（它擅长编码原始代码 token，不擅长编码被抽取的符号名列表）。
- **结论：bi-encoder 与表示的最优组合 = minilm + doc-mode id = 62.3%**（BM25 43.3%，+19pp）。jina 一路彻底出局，不再投入。

### 6.2 「其他好方案」的第二斧：查询期 cross-encoder 精排（实验 3）

- 瓶颈诊断更新：RRF 融合把 BM25 ∪ 语义两路 merge，**语义噪声会把正确文件稀释出 top-K**（EscalationPort 类大 GT 查询 −8.3pp）。这是「融合层」问题，换更好文档向量救不了。
- cross-encoder reranker 直接修这处：对 RRF top-N 候选用 (query, doc) 配对打分重排，把对的文件捞回 top-K。**零重建、查询期、可回退**。
- **模型重定向**：bge-reranker-large(1.6GB) 在本沙箱下载/加载过脆（慢、易 OOM）。改用 **Xenova/ms-marco-MiniLM-L-6-v2（82MB，MS MARCO cross-encoder）**，轻量可靠，本地验证可加载。
- **关键工程坑（值得记）**：transformers.js 的 `text-classification` 管道对「回归式单 logit」cross-encoder 会 softmax 塌缩成 `score:1`（恒 1.0，废）；必须用 `feature-extraction` 管道，其 `out.dims=[batch]`、`out.data` 即每配对的真实相关度 logit（越高越相关）。
- 已落地：`src/ports/reranker.ts` + `src/adapters/reranker/transformersReranker.ts`；`repoMapContext.ts` 注入 reranker（RRF 后、bm25Floor 前，fail-closed）；`buildFileDocTexts` 抽为索引与 reranker 共用的文档表示单一来源；eval 加 `--rerank`/`--rerank-model`。tsc 通过、已编译 dist。
- **实验 3 后台跑中**：`--model minilm --doc-mode id --rerank --ablate`，对照 62.3% 基准，验证能否冲 67%。

### 6.3 还值得挖的「其他好方案」（按 ROI 排序，未全部实施）

1. **cross-encoder reranker（实验 3，进行中）**——融合层去噪，+3~8pp 预期，零重建。
2. **SPLADE / 神经稀疏（learned sparse）**——BM25 的神经扩展（bm42 / SPLADE++），用 ONNX 稀疏编码器把查询与文档扩成词汇表权重向量，与 BM25 同倒排结构但带语义扩展；u1 查询 "retry" 也能命中 "backoff"。代价：需 ONNX 模型（英文 SPLADE 对代码增益有限，代码专用 SPLADE-Code 需自导 ONNX）。Tier-2。
3. **BM25 查询扩展 RM3**——论文实测在 CodeSearchNet（查询极具体）**反而有害**，本语料查询也具体，故低优先级（Tier-3，风险）。
4. **Learning-to-Rank（LambdaMART）**——融合 词法+语义+结构 特征训练 LightGBM；需训练数据（本语料 33 查询 GT 偏少）。Tier-3 重武器。
5. **ColBERT late interaction（token 级 MaxSim）**——存储每文件 token 矩阵，查询期 MaxSim 打分；代码长标识符匹配强，但索引体积/内存大涨。Tier-3。
6. **查询期 HyDE / 查询改写**——用现有 bi-encoder 对 NL 查询生成「假想代码」嵌入，桥接词法鸿沟；抽象查询有效、具体查询反降，需配 reranker。零新模型，可作轻量补充。

> 注：代码感知 BM25 分词（camelCase/snake_case 拆解 + 词形变体）**代码库早已实现**（`tokenizeExpanded`），BM25 地板 43.3% 已是词法极限，调分词器边际很小——故不列为新杠杆。

## 7. 极限瓶颈与跨学科突破框架（元总结）

### 7.1 所有路线卡在 59–62% 的同一道墙

| 单元格        | 表示/模型                      | Hybrid 召回   | 判读                                     |
| ------------- | ------------------------------ | ------------- | ---------------------------------------- |
| 基准          | minilm + 前600字符+符号名      | 59.2%         | 口径基线                                 |
| jina+600      | 代码模型 + 600字符             | 56.1%         | 只换模型不换表示，反降 3.1pp             |
| jina+全文     | 代码模型 + 8000字符            | 54.5%         | 喂更多字符稀释身份信号，反降 4.7pp       |
| **minilm+id** | **浓缩身份(符号名+签名)**      | **62.3%**     | **当前最佳：改"向量装什么"而非"多大"**   |
| jina+id       | 代码模型 + 浓缩身份            | 52.9%         | 代码模型在符号文档上更差，出局           |
| +reranker     | minilm+id + 通用 cross-encoder | 61.3%         | 机制对路、通用模型不懂代码，−1.0pp       |
| e5large+id    | 1024d 容量 + 浓缩身份          | ~68%(Running) | 容量+表示近似可加，唯一可能破 67% 的组合 |

**墙的本质不是"哪个模型"，是范式：**

1. **单向量双编码器表示的信息论瓶颈（rate–distortion）**：一个文件承载多个函数、多个意图、多个查询相关面，却全被投影成一条 384–1024d 向量。mean-pool / 截断必然丢信息。id 表示(62.3%)的增益来自"向量里浓缩了符号名这一身份信号"，**不是来自更大/更多字符**——铁证瓶颈在"表示内容"而非"表示大小"。
2. **双编码器查询期独立打分 = 无联合推理**：BM25 与稠密都只做 query∥doc 各自编码后 NN，无法判断"此文件的实现是否真的满足查询意图"。需 joint attention（cross-encoder），但通用英文 cross-encoder 不懂代码（61.3% 反降）。
3. **文档–查询模态鸿沟**：查询是自然语言意图，文档是代码字符串，嵌入空间存在 gap（HyDE/Late-Chunking 正是在填这缝）。
4. **离线容量墙**：本地 ONNX 实用上限≈e5-large(1024d/323MB)；C2LLM-7B(MTEB 80.75)要 7B 参数，离线跑不动。故"换更大模型"撞硬件/体积墙——容量杠杆已快见底。

### 7.2 能协助突破的学科与思路（按"落地可行性 × 增益预期"）

- **A. 信息论/编码论** — 把"一文件一向量"升级为**多码/多视图表示**（一文件→多向量各捕一面：接口/实现/错误处理/IO）。这是 rate–distortion 里"提码率"。VQ/乘积量化（Jégou）本就出自编码论。**落地：Late Interaction(ColBERT) token 级保块信号、Matryoshka 多分辨率**。
- **B. 语言学/形式语义** — 代码有表层(串)与深层(语义/控制流/数据流)。Montague 组合语义：意义=部分的函子。按"指称"而非"字符串"映射代码，是 AST/CFG 图检索的语义根基。
- **C. 图论/范畴论** — 代码是图(调用/依赖/类型)不是文件袋。图上的随机游走/消息传递恢复扁平向量丢失的结构；范畴论"结构保持映射"=查询是变换、找两类型间的态射函数。**落地：AST 子树哈希、调用图距离作排序特征**。
- **D. 统计力学/重整化群(RG)** — 多尺度表示，文件→模块→函数→块是 RG 流；**67% 是表示的相变临界点**，过了要换"序参量"(结构感知)而非加向量。**这正是我们撞墙的理论解释**。
- **E. 统计/主动学习** — 我们做的 2×2 消融就是析因设计/因果推断；下一步用**贝叶斯优化**在"文档向量里装什么"的空间直接 BO 召回，而非网格搜。
- **F. 认知科学/记忆系统** — 人搜代码不是向量 NN，是索引记忆+联想+精细提取。复用 `rlvrLoop` 回放缓冲做**记忆增强检索**；海马回放/睡眠巩固=按难度周期重索引。免疫类比：阴性选择=拒无关、自适应=难负例挖掘（已部分有）。
- **G. 化学/分子指纹** — ECFP/Morgan 子结构哈希 → **AST 子树哈希作第四路结构信号**，Tanimoto 相似直接套用，**零重嵌税**。
- **H. 最优化/学习排序** — **LambdaMART 融合 词法+语义+结构 特征**，把检索从"一个编码器"重构成"异质信号上的排序问题"，数学融合胜过任何单双编码器。
- **I. 信号处理/稀疏编码** — SPLADE/learned sparse = 保留可解释 token 级信号但学权重 = 压缩感知/过完备稀疏表示(Donoho)。**落地：learned-sparse 过完备字典上的稀疏组合，兼顾可解释+召回**。

### 7.3 推荐的下一条真路线（尊重离线 + 诚实测量纪律）

1. **学习排序 LambdaMART**（H）：BM25 + 稠密 + AST指纹 + 调用图距离 异质信号融合 —— 数学融合，立于单编码器之上，零重嵌税。
2. **AST/子结构指纹第四路**（G）：化学信息学，零重嵌，直接套 Tanimoto。
3. **Late Interaction / ColBERT**（A）：信息论"提码率"，需 `embed` 接口暴露 token 级嵌入（当前未暴露，是真工程量）。
4. **记忆增强/自适应难负例**（F）：认知/免疫，复用 `rlvrLoop` 回放缓冲，把失败查询当"病原体"做在线难负例挖掘。
5. **learned-sparse / SPLADE**（I）：稀疏可解释 + 语义扩展，与现有 BM25 倒排结构同构、易融合。

> 纪律重申：每条路线独立 2×2 受控消融、单一变量、端到端真跑 src/ 实测；增益须 ≥67% 才算破线，不得拿 MTEB 裸分当己用。先可行性门（ONNX 本地能加载+打分）再投入。
